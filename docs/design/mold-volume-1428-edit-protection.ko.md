# #1428 볼륨 편집·삭제 보호 UI 설계

## 계약

#1423 서버 계약을 재사용한다. 이름과 삭제 보호는 Admin/DomainAdmin/User 및 프로젝트 접근 권한을 가진 계정이 변경할 수 있다. 경로는 API 메타데이터에 path가 있고 Admin인 경우에만 다룬다. 이름·삭제 보호 수정은 id와 실제 변경한 필드만 전송한다. account/domainid와 변경하지 않은 path는 전송하지 않는다. 프로젝트 선택 시 공통 요청 interceptor가 projectid 컨텍스트를 추가하는 계약은 유지한다.

경로는 Allocated/Ready/Uploaded, 미연결 또는 연결 VM Stopped, legacy 정책, 압축/중복제거 비활성일 때만 입력을 노출한다. 빈 경로를 금지하고 현재 경로와 수동 참조 변경의 영향을 안내한다. 파일을 이동하거나 복사하는 기능은 아니다. 명시적 할당 정책의 수동 경로 변경은 #1427 서버 가드를 유지한다.

## 제출과 오류

폼이 열린 시점의 대상·계정·프로젝트·화면과 현재 컨텍스트가 같아야 한다. 제출 전에 ID로 최신 볼륨을 재조회하며 프로젝트 자원은 projectid로 조회한다. 소유권, 변경 필드 충돌, 경로 변경 시 path/chain/storage/state/VM 연결을 대조한다. 서버는 실행 시 최종 권한·상태를 다시 검증한다.

검증 시작부터 제출 잠금을 걸어 중복 클릭을 막는다. updateVolume은 POST로 전송하고 공통 비동기 작업 추적 완료 후에만 갱신·닫기를 수행한다. 실패 시 입력·대상과 서버 사유를 유지한다. 작업 ID를 받은 후 결과가 불명확하면 새 쓰기를 하지 않고 같은 작업의 결과를 다시 확인한다. 공통 작업 추적기의 알림 식별자도 같은 작업 ID로 지정하여 재확인 성공 시 이전 미확인 경고를 정리한다. 응답을 받지 못했던 요청이 이미 반영됐다면 최신값과 대조해 재전송 없이 완료한다. 계정/프로젝트/화면 변경 후 늦은 응답은 새 대상에 적용하지 않는다.

## 삭제

보호된 볼륨의 destroy/delete를 모두 비활성화한다. 영구 삭제(deleteVolume)는 모든 상태에서 Admin/DomainAdmin 또는 allowuserexpungerecovervolume 허용 계정에만 노출한다. 일반 사용자·프로젝트의 복구 가능한 삭제(destroyVolume)와 영구 삭제 권한을 구분한다. 일괄 선택에 보호되거나 상태·연결·권한상 삭제할 수 없는 항목이 있으면 전체 동작을 비활성화하고 사유를 표시한다. 기존 fast-clone flatten 차단과 서버의 최종 삭제 보호 거절은 유지한다. 선택 후 보호가 변경되는 경합에서는 서버 거절을 공통 일괄 작업 결과에 그대로 보존한다.

## UI와 검증

기존 VM 편집과 같은 세로형 폼, 취소/확인 버튼을 유지한다. 상세 탭 스타일과 할당 정보 표시는 변경하지 않는다. #1433의 VM 표준 최종 대화상자 비교 대상에 포함한다.

UI 단위/컴포넌트 테스트, lint·production build, 31/32의 Admin/DomainAdmin/User/Project 실제 UI→API→DB 검증, 상태 보존 및 이미지 대조, 오류/재시도·일괄 선택 확인을 수행한다. 전용 계정·역할·프로젝트·오퍼링·볼륨만 생성·정리하고 운영 자원 및 기본 역할 권한을 보존한다. 이번 변경은 UI 모듈뿐이므로 Maven/Agent/전체 Cloud 빌드나 JAR 배포는 하지 않는다.
