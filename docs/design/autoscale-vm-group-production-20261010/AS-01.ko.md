# AS-01 / #1347 생성 사전 검증 설계

Epic #1346의 첫 구현 범위다. 다단계 생성 실패 보상/전체 작업 멱등성(#1348), 정책 계산/스케일링/최종 화면 재구성은 후속 이슈에서 진행한다.

- 빈 UserData id는 조회하지 않는다. 누락된 응답/params/권한 실패는 예외 없이 설명과 재시도를 제공한다. 선택 변경 중 이전 응답은 무시한다.
- AutoScale의 컴퓨트 기본 선택은 활성 고정 오퍼링만 허용한다. 공통 VM 선택 컴포넌트의 일반 VM 동작과 페이지 밖 기존 선택을 보존한다.
- 임계값은 0 이상의 안전한 정수, min/max/interval은 Java int 범위의 양수로 검증한다. min<=max 및 기존 duration>=interval 조건을 유지한다. 삭제 유예의 0은 기존 서버 계약대로 허용한다.
- 생성/사전 조회 API가 없는 역할에는 사유를 보여주고 폼/POST를 차단한다.
- 제출 직전 프로젝트/계정 문맥으로 템플릿 Ready·고정 오퍼링·기본 네트워크 AutoScaling/LB provider·LB 소속망·VM/그룹 미연결·정책 카운터를 다시 조회한다. 하나라도 조회 실패/부적격이면 프로필/조건/정책을 만들기 전에 종료한다. 서버는 최종 권한·동시 요청 검증의 책임을 유지한다.
- 서버의 새 프로필 생성은 소유자의 템플릿 UseEntry 권한 및 오퍼링/Zone 사용 권한, 고정/활성 오퍼링, user VM 이미지 및 해당 Zone 준비 상태를 검증한다. 직접 다운로드 템플릿은 기존 VM 직접 다운로드 계약을 보존한다. 그룹의 프로필/로드밸런서 Zone 일치를 검증한다.
- 프로필 변경 계약은 #1352로 남기고 이번에는 생성 경로만 변경한다. 지원 provider를 새로 광고하거나 런타임 스케일링 상태를 추정하지 않는다.

집중 단위 테스트와 server 변경 모듈 빌드, UI 번들 빌드 후 31 GFS2/32 krbd에서 실제 UI로 정상 생성과 부적격/권한/경계 입력을 확인한다. 새 UI 문자열은 한국어·영어에 등록하고 다크/라이트 가독성을 확인한다. 장시간 운영 확인은 이번 범위가 아니다.

제출 직전에 선택된 UserData와 템플릿 연결 UserData도 다시 조회한다. 조회가 진행 중인 상태에서 제출하더라도 완료를 기다리며, 삭제·권한 변경·변수 정의 변경이 확인되면 자원을 생성하기 전에 중단한다. 기존 변수 입력값은 유지한다.

## GFS2 검증 원칙 및 실 UI 보정

- GFS2 검증 VM은 `SPARSE` 또는 `FAT` 오퍼링으로만 생성한다. `THIN` 사용을 금지하며, 31번 전용 Sparse 오퍼링을 사용한다. 오퍼링 설정과 호스트의 실제 이미지 생성 경로를 함께 검증한다. 기존 Thin 오퍼링으로는 검증 VM을 생성하지 않았다.
- 정책 기간/대기 시간 입력은 그룹 폼이 아니라 선택된 정책 객체에 저장된다. 숫자 검증도 해당 객체를 읽도록 수정하고, 제출 시 모든 정책의 정수 범위를 다시 검사한다.
