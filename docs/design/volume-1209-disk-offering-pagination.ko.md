# #1209 VM 생성 디스크 오퍼링 페이지 처리 설계

Epic #1422 · 누적 Draft PR #1435 · 기준 3073381284f · 2026-10-22

현재 DiskOfferingSelection은 API count 대신 현재 응답 페이지를 KVDO로 필터링한 길이를 total로 사용한다. API가 10개와 count>10을 반환해도 1페이지만 노출한다. 부모 DeployVM은 ROOT/DATA 선택기가 같은 options.diskOfferings를 공유하므로 단순 total 교정만으로는 다른 페이지/검색에서 선택한 객체가 부모의 formModel 재계산 때 사라질 수 있다.

VM 생성은 소유자·도메인·프로젝트·Zone 범위를 보존한 전체 후보를 기존 readAllocationList로 모든 API 페이지에서 수집한다. 완전한 결과만 원자적으로 교체하고, 같은 범위 실패 시 기존 후보/선택을 유지하며 재시도한다. 범위가 바뀌면 이전 후보/선택을 제거하고 늦게 도착한 응답은 적용하지 않는다. 로딩/조회 실패 중 생성은 차단한다.

DiskOfferingSelection에 명시적 allItems 모드를 추가한다. VM ROOT/DATA/ISO 추가 데이터 선택기는 같은 전체 후보에서 독립적으로 KVDO·이름/설명 검색·페이지·쪽당 개수를 계산한다. 미선택은 별도 선택지로 첫 페이지에만 표시하며 오퍼링 count나 슬롯에 포함하지 않는다. 페이지/검색/쪽당 개수만 변경할 때 UUID와 원본 객체는 유지한다. 미선택은 이전 크기/IOPS 객체를 비운다. 필수 ROOT에는 미선택을 넣지 않는다.

기존 다른 부모의 서버 페이지 모드는 API rowCount를 사용하도록 교정하되 서버 조회 계약을 유지한다. 모든 위저드를 한꺼번에 전체 조회 방식으로 바꾸지 않는다. 공용 컴포넌트 회귀는 focused 검사로 확인하고 실환경 완료 주장은 VM 생성 경로로 한정한다.

UI만 변경한다. UI lint·의미 있는 컴포넌트/부모 조회·경합/실패 회귀와 production build 후 31/32의 정적 webapp만 배포한다. 실제 23개 초과 후보로 10/20개 페이지·마지막 페이지·검색/해제·미선택·ROOT/DATA 독립성·허용 범위·조회 실패/재시도 및 선택 ID의 생성 요청/API/DB 연결을 검증한다. 기존 운영 자원·WEB-INF/META-INF/config/JAR/PID와 FT 작업 디렉터리를 보존하며 전용 자원을 정리한다.
