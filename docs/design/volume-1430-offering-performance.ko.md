# VOL-08 디스크 오퍼링 성능 설정과 컴퓨트 디스크 상속

대상: Epic #1422 / #1430. 기존 세로형 상세 목록과 활성/비활성·접근 범위 작업을 유지한다. #1154 링크 오류, #1432 전체 권한 매핑, #1433 전체 UI 통일은 각 이슈가 소유한다.

## API와 편집 책임

| 속성 | 생성·복제 | 디스크 오퍼링 수정 | 컴퓨트 오퍼링 수정 |
|---|---|---|---|
| 이름·설명·태그 | 지원 | 지원, 태그는 도메인 관리자 설정 확인 | 기존 이름·설명·스토리지 태그·호스트 태그 유지 |
| 캐시 | none/writeback/writethrough/hypervisor_default | 지원, 공유 가능 디스크는 none 유지 | 미지원 |
| 읽기·쓰기 B/s·IOPS와 각 burst max/length | 지원 | 12개 항목 지원 | 미지원 |
| 스토리지 최소·최대 IOPS·사용자 지정 여부 | 지원 | 미지원, 읽기 전용 | 미지원 |
| 크기·스토리지 유형·할당 정책·공유·암호화 | 지원 조건은 기존 계약 적용 | 불변, 복제/새 생성 안내 | 불변 |
| 상태·도메인·존 범위 | 기존 계약 유지 | 기존 별도 작업 유지 | 기존 별도 작업 유지 |

Root Admin과 허용된 Domain Admin만 수정한다. 실제 API 메타데이터에 없는 입력은 노출·전송하지 않는다. 내부 관리자 옵션을 일괄 추가하지 않는다. deleteDiskOffering/deleteServiceOffering의 비활성화 계약과 중복 삭제 버튼을 변경하지 않는다.

## 데이터와 입력 계약

- 하나의 QoS 필드 정의·현재값 변환·검증·payload 생성기를 디스크/컴퓨트의 생성·복제와 디스크 편집에 사용한다. 0도 문자열로 보존한다. 숫자의 `.length` 유무로 전송을 생략하지 않는다.
- 단위는 B/s, IOPS, 초. UI는 정밀도 손실 없는 0..9007199254740991 정수를 받는다. API는 LONG 범위의 비음수 정수를 받는다.
- 양수 burst max는 양수 base 이상, 양수 duration은 양수 max를 요구한다. bytes와 IOPS는 서로 다른 제약으로 함께 설정할 수 있다. total 대 read/write 상호 배타는 total API 자체가 없어 UI에 노출하지 않는다.
- 생성·복제의 QoS 종류는 hypervisor/storage/none 중 하나다. 다른 종류의 숨겨진 값을 보내지 않는다. 복제는 해제된 종류에 명시적인 0을 보내 원본의 숨겨진 값이 재상속되지 않게 한다. 편집은 불변인 스토리지 IOPS를 바꾸지 않는다.
- 수정에서 생략/빈 값은 보존, 0은 해당 오퍼링 재정의 해제다. 시스템 기본 제한이 있으면 0 이후에도 적용될 수 있으므로 무제한이라고 단정하지 않는다. burst 해제는 max와 duration을 함께 0으로 만든다.
- 서버가 0을 무시하던 setter를 수정한다. 부분 수정의 base/max/duration은 기존 레코드와 병합한 결과로 검증하고 실패 시 DB에 저장하지 않는다. 음수·잘못된 burst 조합은 생성·복제·수정 모두 거절한다.

## 적용 시점

`ConfigurationManagerImpl.updateDiskOffering`은 레코드를 수정하며 실행 중 VM에 Agent 명령을 보내지 않는다. `VolumeObject`는 `disk_offering_id`로 최신 캐시·QoS를 읽고, attach 및 VM start 시 `VolumeOrchestrator` → `StorageManagerImpl.getDiskWithThrottling` → KVM 디스크 XML 생성으로 전달한다. 따라서 실행 중 XML은 즉시 변하지 않고, 다음 재연결 또는 Cloud 정지·시작에서 최신값을 읽는다. 게스트 OS reboot는 이와 다르다. 실제 31/32 전용 VM의 XML/QMP를 대조해 이 계약을 검증한다.

컴퓨트 전용 자동 생성 디스크는 일반 디스크 목록에서 제외된다. 기존 컴퓨트 편집이 캐시·QoS·CPU·메모리를 변경하는 것처럼 표시하지 않고, 컴퓨트 복제/새 생성으로 안내한다. 일반 디스크 연결형 컴퓨트는 동일 디스크 레코드를 참조하므로 디스크 편집이 다른 연결 사용자에게도 영향을 줄 수 있음을 안내한다. 일반 디스크 연결 시 컴퓨트의 숨겨진 캐시·QoS payload는 생략한다.

KVM burst XML 단위와 유효 조건은 [libvirt 디스크 iotune 문서](https://libvirt.org/formatdomain.html#hard-drives-floppy-disks-cdroms)와 대조했다. RBD에서는 기존 RAW 디스크의 QEMU 캐시·iotune 경로만 검증하며 새로운 falloc/예약/축소 지원을 가정하지 않는다.

## UI와 실패 처리

편집은 대상 이름/상태, 이름·설명·태그, 캐시, 4개 QoS 그룹(기본·burst·초), 각 필드의 현재값, 적용 시점 도움말, 접힌 불변 속성 순서다. 작은 화면은 한 열, 기존 세로 상세 목록은 그대로 유지한다. 읽기 실패는 재조회 전 저장을 막으며 실패 사유를 보여준다. 저장 실패는 입력을 보존하고, 응답을 받지 못한 경우 중복 저장을 막고 서버 재조회를 제공한다. 제출 시작부터 잠가 중복 클릭을 방지한다.

편집의 조회·저장에는 공통 요청 계층의 `preserveOnFailure`를 사용한다. 전송 오류가 전역 로그아웃을 유발해 편집창을 없애지 않도록 하며, 실제 현재 세션의 401 처리는 유지한다. QoS 폼은 모바일의 기존 flex 규칙과 충돌하지 않도록 레이블과 입력을 세로로 배치한다.

복제 원본 조회는 `state=all`로 Inactive도 포함한다. 저장된 디스크 크기 0은 사용자 지정/템플릿 기본 크기 sentinel이므로 새 생성 API에 크기 0으로 전달하지 않는다. 사용자가 명시적으로 요청한 0은 기존 오류 계약을 유지한다. 스토리지 IOPS의 `diskiopsmax`를 하이퍼바이저 burst로 오인하지 않도록 공통 QoS 정의에 있는 필드만 종류 판정에 사용한다. 컴퓨트 CPU·메모리 양수 검증은 유지하고 디스크 QoS의 0은 허용한다.

## 검증과 배포

server Maven 변경 모듈과 UI만 WSL ext4에서 빌드한다. 전체 Cloud 빌드는 실행하지 않는다. 관리 서버의 현재 JAR를 기준으로 필요한 변경만 적용하고 기존 코드/설정과 WEB-INF·META-INF를 보존한다. 31 GFS2·32 RBD에서 전용 오퍼링/VM/볼륨을 사용해 UI 생성·복제·수정, API/DB, 실행 중/정지·시작/재연결의 실제 캐시·iotune, 권한 거절, 기존값/0/경계, 테마·모바일·오류·재시도를 검증한다. 운영 자원을 변경하지 않고 테스트 자원을 정리한 뒤 증거와 함께 #1430을 종료한다.
