# CNI 파일 가져오기·전용 도움말 설계 (#1404)

## 파일 흐름

등록 폼의 CNI 영역에 텍스트/명시적 Base64 파일 주 작업을 추가한다. 파일 선택 취소는 입력을 변경하지 않는다. 파일 크기를 읽기 전에 제한하고 UTF-8을 엄격히 해석한다. 텍스트는 BOM·CRLF/LF·끝 개행을 보존한다. Base64 파일은 기존 canonicalCni 규칙(공백/URL-safe/패딩 정규화)을 재사용하고 BOM/잘못된 문자열을 거부한다. 이름/확장자/MIME만으로 인코딩을 추측하지 않는다. 압축 확장자는 거부하며 ZIP 해제·원격 URL·스크립트 실행은 구현하지 않는다.

읽기 성공은 별도 MoldDialog 미리보기만 연다. 미리보기는 실제 등록할 정규화 Base64를 원문/인코딩 형식으로 표시하며 로컬에서 처리하고 API를 부르지 않는다. ‘본문에 적용’으로만 부모 입력을 변경한다. 부모에는 정규화 Base64와 기존 isbase64=true 계약을 적용해 DOM textarea의 개행 정규화로 원본 바이트가 바뀌지 않게 한다. 이름·변수·소유 범위는 유지한다. 등록/적용 모두 최신 서버 크기 제한으로 재검증한다.

선택마다 세대를 증가시키고 화면/소유 범위/권한 변경·취소·언마운트 뒤 늦은 응답을 폐기한다. 읽기 중 제출/중복 선택을 차단하고 오류·취소·재선택은 기존 입력을 유지한다. 새 컨트롤은 CNI에만 렌더링해 일반 UserData/복제는 기존 계약을 유지한다.

## 도움말과 UI 표준

CNI 메뉴/등록의 docHelp를 local:cni-configuration으로 지정한다. 공용 URL resolver는 이 명시적 표식만 앱과 함께 배포한 ko/en CNI 문서로 연결하고 다른 메뉴의 docBase/section 결과는 그대로 반환한다. 목록·상세 Breadcrumb와 등록/공용 대화상자 소비자가 같은 문서를 사용한다. 기존 SSH 키와 일반 UserData 문서 경로는 바꾸지 않는다.

전용 문서에는 cloud-config 및 Jinja cloud-config 최소 형식, UTF-8/Base64·BOM·개행·크기, 변수 이름 수동 선언과 계정/프로젝트 적용 범위를 설명한다. 서버 KubernetesCniUserData 및 KubernetesClusterStartWorker/NetworkModelImpl 경로를 근거로 설명하며 일반 변수 일괄 문자열 치환이나 실제 설치 성공을 보장하지 않는다. AS_NUMBER의 정확한 특수 표기는 {{ AS_NUMBER }}이다. 예시는 네트워크 플러그인을 설치하지 않는다.

MoldDialog/md·lg, detail-tab-toolbar, UserDataContent의 코드/복사/다운로드 패턴을 재사용한다. 본 화면에는 상시 설명을 추가하지 않고 필요 내용은 전용 도움말과 동적 오류/파일명·바이트에 둔다. #1408 기준의 1440/1024/768/390px × 라이트/다크에서 등록·미리보기·오류·푸터·코드 스크롤/키보드 상태를 실제 31번 UI에서 확인한다.

## 검증 경계

순수 함수/컴포넌트 회귀로 빈 파일·크기 경계·잘못된 UTF-8/Base64·읽기 실패·취소/재선택·늦은 응답·범위 변경·명시적 적용·일반 소비자를 확인한다. 실제 31번에서는 네이티브 파일 선택 → 미리보기 → 적용 → 등록 → API 저장 바이트 및 다운로드 원본을 대조하고 전용 계정/프로젝트의 범위를 확인한다. 원격 읽기 오류 주입과 실제 잘못된 파일을 구분해 기록한다.

UI 정적 배포만 수행하고 WEB-INF/META-INF/config/JAR/PID를 보존한다. Java 변경/Maven 빌드 및 전체 Cloud 빌드는 없다. 생성한 테스트 CNI/계정/프로젝트/도메인을 정상 API/UI로 정리하고 기존 CNI·Kubernetes 안정 필드/노드 UUID·선택 DB 행을 전후 대조한다. #1405 변수 추출/치환 미리보기 및 #1406/#1407 복제/이력은 별도 범위다.

모달은 포털로 렌더링되므로 코드 영역 제한은 CNI 파일 미리보기 전용 클래스에 45vh로 적용한다. 컴포넌트가 제거될 때 부모 reading 상태를 false로 해제해 조건부 제거 후 입력 잠금이 남지 않도록 한다.

최종 스크린샷에서 공통 `.ant-form input[type="file"]` 규칙이 단일 숨김 클래스보다 우선해 네이티브 입력이 중복 노출되는 것을 발견했다. CNI 컨테이너와 입력 클래스를 함께 지정해 우선순위를 높인다. 최종 화면 검증은 파일 입력의 computed display:none 및 너비/높이 0도 확인하고, 숨겨진 입력의 버튼 기반 선택 → 적용 → 저장 경로를 다시 실행한다.
