# 볼륨 마이그레이션·디스크 오퍼링 변경 대화상자

승인한 목업을 기존 크기 변경 대화상자의 입력 중심 배치로 구현한다. 상단 할당 요약과 일반 확인 문구를 제거하고 대상 이름/유형만 간단히 표시한다. 현재 풀·오퍼링·크기·IOPS는 관련 입력 레이블 옆에 표시하고 제약과 조회 실패는 해당 선택란 아래에 둔다. 추가 옵션은 접되 적용 여부를 제목에 표시하며 하단에 변경 요약과 취소/실행 버튼을 둔다.

## 마이그레이션

- 공유 테이블 선택 컴포넌트의 다른 사용처를 변경하지 않는다. 이 대화상자에서만 모든 페이지의 `findStoragePoolsForMigration` 결과를 검색 가능한 선택란으로 표시한다. 현재 풀을 제외하고 Down 등 Up 이외의 풀은 선택할 수 없다. 적합 여부와 여유 용량을 선택란 아래에, 클러스터/Pod·전체/사용 용량·볼륨 크기는 접힌 풀 상세에 둔다. 부적합 표시는 기존 API 의미를 유지하며 오퍼링 교체로 해결할 수 있는 후보를 임의로 제거하지 않는다.
- VM 연결 상태를 표시하고 연결된 볼륨에만 오퍼링 동시 변경 옵션을 제공한다. 오퍼링 조회에는 선택한 풀의 UUID를 전달하며 풀 변경/이전 응답의 경합을 방지한다.
- 명시적 할당 정책 볼륨의 기존 마이그레이션 제한과 `livemigrate` 계약을 유지한다. 조회 실패/빈 후보에서 제출을 막고 입력을 보존해 다시 조회한다.

## 디스크 오퍼링 변경

- 현재 오퍼링을 선택란 옆에 표시한다. 선택된 오퍼링의 사용자 지정 여부로 크기·IOPS 입력을 결정하고 고정값은 읽기 전용으로 표시한다. 첫 목록 항목의 설정을 잘못 적용하지 않는다.
- 현재값을 기본값으로 사용한다. 실제 축소일 때만 해당 입력 아래에 제한 또는 명시적 축소 동의를 표시한다. QCOW2/XenServer 및 명시적 할당 정책의 기존 제한을 유지한다. RBD의 새로운 축소/예약 지원을 추가하거나 보장하지 않는다.
- 자동 마이그레이션 기본값 true를 폼과 요청에서 일치시키고 KVDO에서는 숨겨진 옵션을 전송하지 않는다. 할당 정책이 다른 오퍼링은 선택 불가이고 같은 정책의 변경은 기존 서버 계약에 따른다.

## 검증과 범위

숫자·최소/최대 IOPS·축소 동의, 정확한 풀 UUID, 페이지 수집, 조회 실패/재시도, 중복 제출과 이전 응답 차단을 회귀 검증한다. UI 모듈만 WSL ext4에서 빌드한다. 31(GFS2)/32(RBD)에 정적 자산만 배포하고 `WEB-INF`/`META-INF`/config/JAR/PID와 운영 자원을 보존한다. 실제 UI에서 실행 가능한 오퍼링 변경과 API/DB/이미지 결과를 대조하고 마이그레이션은 현재 후보 인벤토리에 따라 실행 또는 제한/취소를 검증한다. 후보가 없으면 실물 마이그레이션 성공으로 보고하지 않는다.

두 대화상자는 500px 기준 폭과 모바일 한 열 배치를 사용한다. 기존 Epic 브랜치와 누적 Draft PR #1435에 반영하며 이 수정만으로 잔여 Epic 이슈를 종료하지 않는다.
