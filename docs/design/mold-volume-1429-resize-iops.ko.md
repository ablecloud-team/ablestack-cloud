# #1429 대상 오퍼링 기준 볼륨 크기·IOPS 변경

## 계약과 범위

resizeVolume의 기존 Backend 계약을 사용한다. DATADISK는 diskofferingid와 정확히 일치하는 listDiskOfferings(id, state=all) 응답만 사용한다. 전체 목록의 첫 항목, 페이지 크기, 다른 볼륨의 오퍼링을 사용하지 않는다. 빈 응답·다른 ID·중복 응답은 제출을 차단한다.

compute-only ROOT는 listVolumes에서 diskofferingid 대신 내부 숫자 serviceofferingid를 반환할 수 있고 listDiskOfferings에서 제외된다. 이 숫자를 UUID API에 전달하지 않는다. 해당 볼륨의 virtualmachineid로 VM을 조회하고 그 VM의 serviceofferingid(UUID)를 정확히 조회한다. 연결된 디스크 오퍼링과 이름 일치도 확인한다. ROOT IOPS는 Backend가 고정/사용자 지정 여부와 무관하게 재정의를 허용하므로 입력을 제공한다. 일반 디스크의 고정 IOPS는 읽기 전용이다.

## 입력과 요청

현재 size/GiB, miniops, maxiops를 초기화한다. 변경하지 않은 값·빈 값은 생략하고 현재값을 유지한다. 0은 명시적인 IOPS 값이며 정수·안전한 숫자 범위·최소≤최대·null 쌍 제약을 검증한다. size만, IOPS만, 동시 변경을 허용한다. 오퍼링 전환 ID를 요청에 섞지 않는다. shrinkok/automigrate는 관련 크기 변경에만 소문자 API 키로 보낸다.

명시적 할당은 #1427과 같이 물리 크기 변경을 막으며 IOPS 단독 변경을 허용한다. 엄격한 고정 크기, 컴퓨트 오퍼링의 루트 고정 크기도 안내한다. ROOT 고정 크기는 템플릿 기반일 때 Backend가 거절하며 ISO 기반 예외가 있으므로 안내를 표시하되 일괄 차단하지 않는다. QCOW2 Ready/XenServer 축소는 차단하고 다른 지원 경로에는 축소 동의를 요구한다.

## 오류·동시성

제출 전 listVolumes와 정확한 오퍼링을 재조회해 크기·IOPS·경로·체인·풀·상태·연결·소유자·할당 의도 및 계약이 달라지면 요청하지 않는다. 사용자/프로젝트/대상 변경과 중복 제출을 차단한다. API가 최종 권한과 실행 시점 상태의 검증자이며 조회 후 외부 동시 변경까지 잠그는 것은 아니다.

조회·동기 API·비동기 작업 실패는 서버 사유와 입력을 유지한다. 초기 조회 오류는 재시도 버튼으로 복구한다. 작업 ID를 받은 후 조회가 실패하면 결과 확인은 같은 작업만 조회하고 재제출하지 않는다. 작업 성공 후에만 닫기와 새로 고침을 수행한다. 작업 ID를 받지 못한 모호한 응답은 상태를 확인하고 다시 열도록 안내한다.

## 검증

단위 검증은 대상 오퍼링·ROOT 관계·payload·음수/소수/범위/순서·빈 값·상태 전환·권한·중복·오류 보존을 확인한다. 실제 검증은 31 GFS2와 32 RBD에서 전용 자원으로 UI 요청, API/DB 값, qemu-img/RBD 크기와 경로 및 데이터 패턴을 연결한다. 운영 자원은 변경하지 않는다. VM 생성 오퍼링 목록 페이지 문제 #1209는 별도 범위로 유지한다.
