# CNI 삭제 확인·완료 UX (#1403)

CNI 삭제는 전용 self-managed MoldDialog를 사용한다. 일반 UserData의 삭제 화면과 서버 계약은 변경하지 않으며, 검증된 UUID/소유자 스냅샷·조회·오류 유틸리티와 항목별 결과 처리 패턴을 재사용한다. 기존 groupAction 메타데이터를 CNI 목록의 체크박스·명명된 도구모음에 연결하고 부분 성공은 성공한 원래 UUID만 제거한다.

## 대상과 사용 여부

선택 시 이름·UUID·계정/도메인/프로젝트를 동결한다. CNI의 listCniConfiguration/cniconfig 식별 조회 → 명시적 CNI/소유 범위의 listKubernetesClusters → 식별 재확인을 사용한다. UUID 변환의 431은 즉시 삭제 완료로 보지 않으며, 완전한 owner/name 목록에서 원래 UUID 부재를 확인한다. 같은 이름의 대체 UUID는 삭제하지 않는다.

모달은 이름·UUID·소유 범위·항목별 상태/사유·최신 사용 클러스터 수와 사용처 탭 링크를 제공한다. 확인 중/권한 없음/필터 미지원/조회 실패는 0건과 구분하고 삭제를 막는다. 미사용 확인 후에만 삭제 버튼을 제공하며 제출 직전 식별/사용처/식별을 다시 확인한다. 확인 직후 참조 생성 경쟁은 #1399 서버 잠금/참조 보호가 최종 판정한다. 오류는 서버 사유와 현재 조회 상태를 함께 표시한다.

## 요청과 결과

삭제/결과 확인 중 중복 실행·모달 닫기·Escape·라우트 이동을 막는다. 로그인·프로젝트·화면·대상·권한 변경 및 unmount 이후 응답은 후속 삭제/목록 이동을 일으키지 않는다. 타임아웃/불완전 성공 응답은 원래 UUID를 재조회하고 현재 존재하면 실패, 부재면 성공, 판정할 수 없으면 결과 미확인으로 둔다. 결과 미확인은 명시적 확인 전 자동 재전송하지 않는다.

전부 삭제/부재가 확인되면 모달을 닫는다. 실패/사용 중/결과 미확인은 모달과 원래 선택을 유지한다. 부분 성공 후 닫으면 성공만 제거하고 나머지 선택을 보존하며 목록을 새로고침한다. 참조 갱신 후 미사용이 확인되면 실패한 원래 대상만 재시도할 수 있다.

## 목록 복귀와 캐시

CNI 목록의 이름/코멘트 링크는 지원하는 검색·페이지·정렬·소유 범위를 cnireturn UI 전용 값으로 상세 URL에 보존한다. 허용된 키/문자열만 저장·복원하고 경로는 항상 /cniconfiguration으로 고정한다. cnireturn은 API에 보내지 않는다. 직접 상세로 진입한 경우 현재 URL의 허용된 목록 값 또는 기본 목록을 사용한다.

현재 상세 삭제 완료 시 읽기 세대를 무효화하고 resource/items/count/선택/로드 캐시를 먼저 비운다. 원래 목록 위치로 router.replace하여 삭제 상세와 작업 메뉴를 남기지 않는다. 일반 목록의 기존 마지막 페이지 보정 동작을 사용한다. 프로젝트/로그인 범위가 달라졌으면 옛 위치로 이동하지 않는다.

## 검증·배포

집중 테스트로 실제 API 키·소유 범위·식별/참조 순서·무필터 대체 금지·경합·권한/조회 실패·이미 삭제·불명확 결과·부분 성공/재시도·지연 응답·라우트/캐시·일반 UserData 회귀를 확인한다. lint/production build 후 정적 UI만 배포하며 JAR/PID/WEB-INF/META-INF/config를 보존한다. Maven/전체 Cloud 빌드는 없다.

31번에서 전용 개체로 취소·성공·검색/페이지/프로젝트 복귀·사용 중·조회/권한 오류·삭제 직전 참조 생성·이미 삭제·부분 성공과 일반 UserData 삭제를 검증한다. 전용 개체를 정상 API로 정리하고 API/DB 기준선 및 호스트 잔여를 대조한다. 전체 메뉴 스타일 완료는 #1408에 남긴다.
