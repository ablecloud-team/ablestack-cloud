# #1433 설계: 볼륨·오퍼링 VM 표준 UI 통일

기준 소스는 Epic #1422 브랜치의 `15c14ce1d704e2d21286eb5a56490d5dce3259d8`이다. VM과 세 메뉴가 이미 사용하는 `AutogenView`, `ResourceView`, `InfoCard`, `DetailsTab`, `ListView`, `ResourceActionMenu`를 유지한다. 31번 실제 VM 목록·상세와 미연결 테스트 볼륨에서 기준 화면과 `#/vm/undefined` 결함을 확인했다.

| 화면 | 공통 기준 및 변경 |
| --- | --- |
| 목록 | 기존 VM 공통 헤더·검색·필터·페이지·열 선택·행 작업을 재사용한다. 미연결·삭제 중·조회 권한 없는 VM 관계는 텍스트로 표시한다. 같은 범위의 재조회 실패는 기존 데이터와 세션을 유지하며 오류·재시도와 작업 차단을 제공한다. |
| 상세 | 요약 카드·UUID 복사·작업 메뉴와 기존 세로형 상세를 유지한다. 요청/확정/실제 할당 정보와 관측값의 의미를 변경하지 않는다. |
| 탭 | 컴퓨트 오퍼링의 VM, 디스크 오퍼링의 볼륨, 볼륨의 스냅샷 탭을 명시적 읽기 API로 구성한다. 권한 없는 탭은 숨기고 유효한 탭으로 URL을 보정한다. |
| 탭 콘텐츠 | `ListView`와 VM 탭 툴바·페이지 스타일을 사용한다. 검색·페이지는 URL에 보존하고, 탭·탭 검색 변경만으로 부모 상세를 초기화하지 않는다. 이전 자원·프로젝트의 늦은 응답은 폐기한다. |
| 대화상자 | 기존 `components/view/MoldDialog.vue`와 MOLD-DIALOG-1.0 `md/lg` 프리셋을 재사용한다. 기존 입력 순서·그룹·조건부 필드·입력 옆 현재값은 유지한다. 대화상자 수준 버튼만 `MoldDialogActions`를 통해 단일 고정 푸터로 연결한다. |

`MoldDialogActions`는 Vue Teleport를 사용한다. 폼의 Vue 부모·검증·이벤트 소유권을 유지하므로 버튼 이동을 위해 폼을 복제하거나 별도 제출 경로를 만들지 않는다. 공통 쉘이 없는 기존 호출에서는 원래 위치에 표시한다. 작업 중에는 취소·중복 실행·닫기·Escape를 잠근다. 스냅샷 정책의 두 탭은 입력을 보존한 채 활성 탭의 버튼만 푸터에 표시한다. 행 추가·태그 편집·정책 삭제 등 내부 작업은 본문에 남는다.

조회 실패는 각 폼이 처리하도록 `storageApi` 읽기 어댑터가 기존 `preserveOnFailure` 계약을 사용한다. 현재 세션의 실제 HTTP 401 인증 실패 처리는 공통 인터셉터에 남긴다. 신규·복제 오퍼링과 볼륨·스냅샷 생성은 비동기 검증 직후 잠금과 원래 자원·사용자·프로젝트·경로를 다시 확인하여 늦은 검증이나 이중 클릭으로 다른 대상을 요청하지 않게 한다.

#1212의 미병합 로컬 생성 폼 구현을 완료로 합산하지 않는다. 현재 브랜치에 이미 포함된 공통 쉘·토큰을 직접 재사용하며 별도 모달 쉘·색상 토큰을 만들지 않는다.

검증은 전용 `VOL1433-*` 자원으로 31(GFS2), 32(RBD)에서 수행한다. UI 모듈만 빌드하며 관리 서버 JAR·프로세스·서버 측 WEB-INF/META-INF와 기존 정적 파일은 보존한다. RBD 할당 정책·스토리지 엔진 동작은 변경하지 않는다. 전체 할당 정책 행렬의 최종 회귀와 Epic 통합 종료는 후속 #1434의 범위다.
