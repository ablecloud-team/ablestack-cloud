# #1488 스냅샷 대화상자 설계

기준 HEAD `ae174ed6eac5a4b07ade1e305a9ca890be9bf8a2`, Epic 브랜치 `dhslove/epic-1473-storage-snapshots`.

## 범위와 표준

스냅샷 생성, 새 볼륨 복구, 템플릿 생성, 원본 되돌리기, 다운로드 준비, 복사, 보관, 단일/다중/Zone 삭제 및 관리자 잔여 삭제 복구를 검토한다. 결과는 기존 알림과 공통 작업 상세에 유지한다. 새로운 상세 탭/작업 저장소/API 규칙을 추가하지 않는다.

VM 공통 MoldDialog의 md=720px, 다중 대상은 lg=960px 프리셋을 사용한다. 공통 고정 헤더/푸터·본문 스크롤과 24px 폼 항목/8px 레이블 간격을 적용한다. 좁은 화면에서는 기존 24px 외부 여백과 16px 본문/푸터 패딩을 사용한다. 표는 내부 가로/세로 스크롤을 제공하고 문서를 늘리지 않는다. 헤더·본문·레이블·선택값·오류·비활성 컨트롤은 기존 테마 토큰을 따른다.

## 대상 정보와 영향

생성/템플릿/볼륨 생성은 상세 페이지의 중복 UUID 표를 보여주지 않는다. 검증 실패·미종결 작업·원본 소실의 의미 있는 안내만 공통 compact Safety로 표시한다. 되돌리기는 기존 승인된 이름/영향 문장을 유지한다. 복사는 고정된 스냅샷 이름·원본 Zone/스토리지와 대상 지원 사유를 표시하고 StorPool 전용 옵션을 제공하지 않는다.

삭제는 복구와 구분해 필수 대상 요약을 남긴다. 단일 대상은 이름·원본 볼륨·한글 상태·가상 크기·주기·시간·삭제 범위이며, 다중 대상은 같은 열을 갖는 공통 표다. 같은 스냅샷이라도 Zone이 다르면 별도 고정 대상 키를 사용한다. Zone 삭제의 제목/영향 문장은 선택 Zone 전체의 Primary·Secondary와 다른 페이지 사본까지 포함함을 명시한다. 전역 삭제와 개별 스토리지 사본 삭제를 혼동하지 않게 한다.

## 상호작용과 안전

실행 버튼은 생성·템플릿 생성·복사·보관·다운로드 준비·복원·삭제처럼 구체적인 작업명을 사용한다. 삭제/되돌리기는 위험 버튼과 명시적 확인을 유지한다. 처리 중 닫기·Escape·확인/변경 버튼은 잠그며, 조회 오류는 입력 보존과 인라인 재시도로 복구한다. 템플릿 옵션 조회는 세대 번호와 기존 보안/자원 범위를 함께 확인해 늦은 이전 조회가 새 옵션을 덮어쓰지 않게 한다.

Ctrl+Enter는 생성/템플릿/복사 본문에서 기존 안전한 제출 함수에 직접 연결한다. 고정 푸터로 이동한 버튼에서 keyup을 기다리는 방식에 의존하지 않는다. 위험 작업은 체크 및 실행 버튼의 명시적 Enter로만 실행한다. Zone 탭의 복사/삭제를 닫으면 원래 실행 버튼 또는 현재 Zone 업데이트 버튼에 초점을 돌리고, 범위가 바뀌면 이전 화면의 초점을 복원하지 않는다. 일반 작업의 기존 Autogen 초점 복귀와 AntD 포커스 트랩을 재사용한다.

SS-06/SS-08의 고정 대상, 최신 상태·범위 해시 재검증, customjobid/registry 잠금과 결과 미확인 시 재제출 차단을 그대로 사용한다. 다중 작업의 부분 완료는 알림/결과 표로 표시하고, 실패 시 이미 완료한 항목을 제외해 다시 선택하도록 안내한다. 이 UI 정리에서 삭제·복사 업무 가용성 규칙을 복제하지 않는다.

## 검증 계획

31 GFS2·32 RBD에 새 `SNAPDIALOG1488-*` 전용 자원을 만들고 UI 요청/응답과 async_job·DB 결과를 독립 대조한다. 생성·복원 볼륨·템플릿·되돌리기·다운로드·보관·복사·단일/다중/Zone 삭제 및 잔여 진단의 실제 지원 조건과 제출을 확인한다. 입력 오류, 조회/제출 실패와 재시도, 중복 클릭, 늦은 응답·대상/범위 전환은 통제된 요청/응답 장애와 실제 권한·상태를 구분해 기록한다.

각 대화상자의 라이트/다크 × 390/768/1280px, 긴 이름, 다중 대상 스크롤, 헤더/푸터 고정, 컴포넌트 겹침, 폼·본문 가로 넘침, 포커스·Enter/Escape/Ctrl+Enter를 검사한다. 기존 VM 대화상자와 공통 컴포넌트 회귀를 확인한다. 전체 Cloud/Maven/Actions dispatch는 시작하지 않고 UI 집중 검사·빌드 및 실환경 결과와 구분한다. 테스트 후 정상 API로 정리하고 API/DB/스토리지 활성 잔여 0, 운영 자원과 dirty FT 작업 보존을 확인한다.

## 실화면 확인 후 초점 보완

태그 편집 입력의 제거와 삭제 진단 버튼 비활성화 후 BODY로 초점이 빠지는 현상을 재현했다. 태그 확정/취소/삭제는 태그 추가 버튼으로 명시적으로 돌린다. 공통 MoldDialog에는 snapshotStandardDialog 계열만 활성화하는 focusGuard를 추가한다. 자신이 소유한 열린 modal의 DOM 변경 후 초점이 BODY일 때만 본문에 유지하며, 다른 살아 있는 컨트롤이나 포털의 초점은 건드리지 않는다. 일반/기존 VM 대화상자는 기본 false로 렌더 구조를 유지한다. 삭제 복구는 단일 대상 md=720px으로 맞추고, 영문 API 설명은 툴팁에 남기며 폼 placeholder는 한글 레이블을 사용한다.
