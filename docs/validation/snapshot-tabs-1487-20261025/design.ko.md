# SS-14 스냅샷 탭 표준화 설계 (#1487)

기준 커밋 `662454e38a0991f976f0a2f4a9d6b6ff057d3101`, Epic 브랜치 `dhslove/epic-1473-storage-snapshots`.

## 공통 탭 기준

VM 상세와 같은 ResourceView 탭 및 DetailTab 툴바·표·페이지를 재사용한다. 이벤트·코멘트는 별도 저장소나 스냅샷 전용 대체 컴포넌트를 만들지 않고 공통 EventsTab/AnnotationsTab을 보완한다. 변경된 공통 동작은 전용 VM 탭에서도 비교 검증한다. 새 모달은 만들지 않는다. 복사·Zone 삭제·보관은 기존 VM 표준 MoldDialog와 최신 상태/대상 고정 안전 흐름을 유지한다. 코멘트의 기존 공개 범위/삭제 popconfirm은 공통 VM 탭에서 동일하게 사용한다.

Zone 툴바는 선택한 Zone 삭제 → 업데이트 → 열 선택 → 오른쪽 검색 순서다. Zone/논리 상태/주기/현재 페이지 사본 건수와 작업을 표시하고, 하위 표에 모든 사본 ID·역할·저장소·상태·가용성·가상 용량·진행/오류를 표시한다. 상태·수동/정기 주기와 알려진 다운로드 상태를 번역하고 0·미확인 용량을 구분한다.

Zone 페이지 단위는 SS-07의 서버 사본 페이지다. 같은 Zone의 현재 페이지 사본을 묶을 뿐 전체 조회 건수를 중복 제거하지 않는다. 검색은 API가 지원하지 않는 전역 스토리지 검색으로 오해되지 않도록 **현재 페이지 Zone·스토리지 검색**으로 명시한다. 매칭된 Zone의 사본은 일부만 숨기지 않고 모두 보여 준다. 검색/페이지/대상/권한 전환 시 선택을 초기화하고, 삭제는 현재 페이지를 넘어 해당 Zone 전체에 적용된다는 기존 안내를 유지한다.

이벤트는 공통 ListView·열 선택·서버 keyword 검색·서버 페이지를 사용하고 `snapshot.extract/copy/on_primary/off_primary` 번역을 추가한다. 코멘트는 기존 공통 입력·공개 범위·작성자/시간·삭제·10개 페이지를 유지하며 긴 텍스트와 다크 모드에 맞게 표시한다. 이벤트의 설명 본문은 서버 감사 기록이므로 임의로 재작성하지 않는다.

## 갱신과 소유 범위

사용자/역할/세션/프로젝트/자원 유형·ID/API 권한 및 tab을 제외한 경로를 읽기 범위로 사용한다. tab URL만 바뀌면 동일 요청을 중복 제출하지 않는다. 사본·이벤트·코멘트 응답의 건수, 페이지 길이, ID 중복, 다른 자원 혼입을 검사한다. 범위가 바뀌면 이전 행·건수·선택·입력/오류를 비우고, 늦은 이전 응답·변경 완료는 새 화면에 반영하지 않는다.

동일 페이지 갱신 중에는 행·건수를 유지한다. 503 등 일시 오류는 오래된 결과/재시도로 표시한다. 401/403/404/431/432/531 접근·소실 오류는 이전 정보를 비운다. 실패와 정상 0건을 구분하고 요청에는 20초 제한을 둔다. 삭제로 마지막 페이지가 사라지면 유효한 페이지로 이동한다.

코멘트 쓰기는 현재 범위의 읽기 성공·권한·대상 행 소유 관계를 확인하고 단일 변경 잠금을 사용한다. 실패 시 입력과 공개 범위를 보존하고 오류를 표시한다. 성공 시 제출한 입력만 지우고 새로 입력한 내용은 유지한다. 삭제/공개 범위 변경도 대상·범위를 고정하며 이전 대상의 완료가 현재 탭을 갱신하지 못하게 한다.

## API·DB와 실환경 검증

31(GFS2)/32(RBD)에 독립 전용 도메인·계정·프로젝트·VM·볼륨·스냅샷을 만든다. 주 대상 코멘트 26개(관리자 전용 1개)와 실제 이벤트 30개로 여러 페이지를 검증한다. SQL은 annotations 및 event와 snapshot/account/domain을 연결해 별도로 확인한다. 이벤트는 자원 소유 권한뿐 아니라 행위자의 계정·도메인과 명시적 프로젝트 범위에 따라 조회되므로 DB 비교에도 같은 계약을 적용한다. 감사 이벤트나 정상 삭제 이력은 수동으로 지우지 않는다.

실제 UI에서 툴바/열/검색/페이지, Zone 선택과 영향·복사 대상 조회·보관/삭제 안전 대화상자, 코멘트 생성/실패·재시도/공개 범위/삭제, 소유자·다른 계정·프로젝트·도메인 관리자·읽기 전용 역할과 라이트/다크 390/768/1280px를 확인한다. 실제 실패를 만들지 않고 주입한 503/403/누락·불완전 응답/늦은 응답은 명시적으로 구분한다. 다수 Zone/사본이 없는 환경의 페이지 양성 경계는 응답 주입으로 검증하고 실물 다중 Zone 검증으로 보고하지 않는다.

전체 Cloud CI는 별도 요청 범위다. 이후 #1488 대화상자 최종 정리, 마지막으로 #1489 통합 회귀를 수행한다.

## 최종 배치와 키보드 보완

이벤트 표는 공통 ListView의 선택적인 tableScroll prop과 70~280px 열 폭을 사용해 좁은 상세 영역 안에서 가로 스크롤한다. 다른 ListView 호출의 기존 설정은 유지한다. 코멘트는 입력란의 Ctrl+Enter keydown에서 안전한 saveNote를 직접 호출한다. 기존 공통 directive가 툴바로 포커스를 이동한 뒤 editor 범위에서 keyup을 받지 못하는 문제를 제거하고, toolbar가 editor 밖에 있는 실제 구조로 회귀 검사한다.
