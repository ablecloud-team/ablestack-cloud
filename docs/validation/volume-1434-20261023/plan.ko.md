## 실행 원칙

- 준비된 개체, API 성공, UI 결과, DB, 실제 이미지와 게스트 증거를 구분한다. 과거 검증은 추적 연결에 사용하고 이번 실증을 대체하지 않는다.
- 환경은 각각 적격 Primary가 하나다. 실제 이동에는 전용 두 번째 풀을 준비하고 Cloud UUID·경로/이미지·데이터 동일성을 확인한다. 운영 풀의 설정을 바꾸지 않으며 시험 풀에 운영 자원이 생기면 이를 삭제하지 않는다. 같은 물리 장치를 공유하는 시험 풀은 독립 장애 영역 검증으로 확대하지 않는다.
- 현재 기존 Rocky 9.5 템플릿은 100GiB다. ROOT 검증은 실제 템플릿 크기로 실행한다. 실행/파일 QGA 명령은 템플릿에서 차단되어 있어 게스트 I/O는 새 시험 VM의 키 기반 SSH를 사용한다. 전용 Source NAT/포워딩은 검사자의 단일 /32에만 허용하며 자동 전체 CIDR 방화벽 생성을 끈다. 운영 VM·게스트 보안 설정은 변경하지 않는다.
- 미지원 정책 작업은 명확한 거절·무변경을 검증한다. RBD QCOW2/falloc/lazy thick·영구 용량 예약을 지원으로 분류하지 않는다. #1437의 커널/호스트 근본 수정은 종료 조건에 포함하지 않고 완료된 제품 회피 경로를 회귀한다.
- 실물 실패를 수동 교정하거나 준비 방식을 변경한 경우 원래 결과와 재검증을 별도 기록한다. 필수 미검증·미해결 제품 결함을 완료로 바꾸지 않는다.
- 전체 Cloud/Release 빌드는 실행하지 않는다. 변경이 생긴 Maven 모듈만 WSL ext4에서 빌드하고 qemu-exec-tools 변경이 필요하면 별도 GitHub Actions 규칙을 적용한다. PR 병합은 이번 범위가 아니다.

이 문서는 실행 계획이며 PASS 보고서가 아니다. 실제 판정은 결과·지원/차단/미검증 표와 정리 증거를 모은 최종 보고서에 기록한다.
