# #913 네트워크 준비·기본 경로 지속성 설계

기존 Epic 브랜치와 SharedFS 네트워크 입력/저장 구조를 재사용한다. 최신 upstream4bd1a2cff50을 로컬 ablestack-europa에 먼저 반영해0/0을 확인했으며 시작 commit은343ba01858a이다. 새 이슈·브랜치·PR은 만들지 않고 기존 Epic PR1271에 통합한다. 최종 UI 표준 정리1275는 미착수다.

## 재사용 및 실제 보완

- SharedFSServiceImpl의 gateway 특수주소·CIDR·self/network/broadcast 거절, STATIC primary 보호, 정식 NIC CAS 복구를 재사용한다. 같은 CIDR 안의 특수주소와 primary/alias 보존 회귀를 추가한다.
- 기존 VM의 구형 init.sh SharedFS 분기도 정적 상태 파일이 있으면 setup_common을 실행하지 않도록 정확한 기존 분기만 교정한다. monitor/init 두 파일을 모두 사전 검증하고 이미 교정됐으면 inode를 바꾸지 않는다. 다른 역할·설정은 보존하며 알 수 없는 형태는 변경하지 않는다.
- 현재 KVM QGA가 설치하는 inline helper/unit은 최신 부팅 경로와 다르다. canonical 네트워크 helper와 network/reconcile/DHCP 유닛4개를 template source에서 단일 관리하고 KVM resource에 같은 바이트로 포함한다. 실제 배포도 wrapper와 이 resource만 기존 호스트 JAR에 반영한다.
- 상태 파일의 schema1/mode를 지원하고 기존 mode 없는 STATIC JSON도 읽는다. 유효한 STATIC 상태를 읽을 수 없으면 DHCP로 임의 전환하지 않는다. mode 없는 상태 파일 부재만 기존 DHCP 준비 경로로 처리한다.
- MAC으로 NIC를 찾고 STATIC IP/prefix·connected route·선택 gateway/DNS를 적용한다. 이미 일치하는 primary/alias와 route는 유지하며 다른 NIC는 변경하지 않는다. gateway가 없으면 해당 NIC에 default route가 없어야 한다.
- STATIC NIC의 DHCP unit을 stop/mask하고 실제 dhclient를 정확한 NIC·argv·root executable·PID/startTicks·network namespace에 결합해 종료한다. 다른 NIC/namespace의 DHCP는 제외한다.
- network readiness는 cloud-preinit 이후 실행되며 Storage reconcile은 준비 성공 후 실행한다. QGA는 네트워크 준비와 독립해 L2 첫 부팅에서 STATIC JSON 주입이 가능해야 한다. 진행 중 DHCP 대기는 유한하며 STATIC 주입 뒤 수렴한다. 부팅 의존성 cycle을 실제 systemd 검사와 새 VM 부팅에서 확인한다.
- 적용/읽기 검증에 같은 effective DNS 정책을 사용한다. 정상 AD JOINED 설정이 소유하는 DNS는 static fallback보다 우선하며 이번 이슈에서 AD 가입/탈퇴는 수행하지 않는다.
- monitor에 schema1 networkReadiness를 추가한다. expected/actual mode·MAC·IP·prefix·gateway·DNS·NIC·DHCP unit/process·관측시각과 mismatch를 제공한다. 관측 불능은 UNKNOWN, 확인한 불일치는 ERROR로 표시한다. API의 기존 health cache를 통해 UI에 전달한다.
- UI는 기존 STATIC 선언 정보를 유지하고 실제 관측과 불일치 원인을 보완한다. 잘못된 gateway 입력을 차단하고 monitor ERROR를 정상 초록색으로 표시하지 않는다. 전체 상세 화면 레이아웃은 변경하지 않는다.

## 배포와 실제 인수

기존 템플릿의 전용 VM65(10.10.13.236/16, gateway10.10.0.1, ROOT/DATA SPARSE)를 만들어 QGA 교정 전후와 정상 재부팅을 검증한다. 새 helper/unit이 포함된 정규 Packer SystemVM 이미지는 고정 source·SPARSE metadata preallocation·RAM 전용 TEST 서명으로 빌드하고 독립 이미지 readback 뒤 private 시험 템플릿으로 등록한다. 운영 기본 템플릿을 교체하지 않는다.

| 게이트 | 확인할 증거 |
|---|---|
| STATIC+gateway | 생성 직후와 정상 재부팅 후 MAC/IP/prefix/정확한 default route/DNS 유지 |
| protocol 복구 | 동일 DATA/파일·Native generation을 보존하며 NFS/SMB/iSCSI/NVMe-oF listener와 자원 복구 |
| DHCP 충돌 | exactNIC unit 재시작 차단, 잔존 프로세스 종료, 실제 짧은 lease 갱신 경계를 넘는 STATIC 유지 |
| no gateway | 새 시험 VM에서 connected route만 존재, 해당 NIC default 없음 |
| DHCP | 기존 격리망의 정상 DHCP 생성·재부팅·주소/route/DNS 복구 |
| 다른 NIC명 | MAC으로 eth0 이외 NIC를 찾아 실제 네트워크 적용/검증 |
| invalid gateway | self/network/broadcast/offCIDR/0/loopback/linklocal/multicast를 API 및 실제 UI에서 거절 |
| 오류·복구 | 소유 시험 VM만 route 불일치를 주입, monitor/API/실제 UI ERROR 후 정식 helper로 복구 |
| 기존 VM | 실제 QGA installer의 제한 경로로 교정, 기존 서비스 PID/IO/파일/설정 보존 |
| 신규 template | helper/unit/source manifest 일치, fresh boot의 network→reconcile 순서와 STATIC/DHCP 동작 확인 |

파일·자원 생성은 이슈 전용 scope로 제한한다. 신규 디스크는 SPARSE/FAT만 사용하고 THIN은 만들지 않는다. 원본 F1/VM54, 보호 partial021b/VM51, ref59 및 복구 검토 VM61은 조회로만 보존을 확인한다. 기존 복구 필요10행과 전역 용량 설정도 유지한다. 네트워크/템플릿 문제를 다른 신규 이슈로 분기하지 않고 이 이슈의 실제 완료 게이트와 남은 상태를 기록한다.
