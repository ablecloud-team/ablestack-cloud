# #1490 설계·검증 계획

기준 Europa: `bb40d23119e3554774471f262ddf6a61645f67a1`. 작업 브랜치: `dhslove/issue-1490-snapshot-dialogs`.

31번 기존 화면에서 정기 스냅샷 대화상자를 연 뒤에도 `#zone-selection`의 상위 `.ant-select-loading`이 남는 것을 재현했다. 원래 볼륨에는 정책을 등록하지 않았다.

`FormSchedule`은 `zoneLoading`을 data에 선언하지 않고 생성 과정에서 동적으로 추가한다. Vue 3에서 이 값은 반응형 필드가 아니므로 Zone 응답이 끝나 `false`를 대입해도 로딩 표시 갱신이 보장되지 않는다. 즉시 생성 대화상자에도 같은 조회 코드가 중복되고 오류 처리·재시도가 없으며, 지원하지 않는 복제 기능을 위해 별도 스토리지 목록을 읽는다.

두 대화상자에 `snapshotZones` 믹스인을 적용한다. Zone 목록·로딩·오류를 처음부터 반응형 데이터로 선언하고, 전체 페이지를 읽은 후 현재 Zone과 Edge를 제외한다. 요청은 페이지당 20초로 제한하고 성공/빈 목록/실패에서 로딩을 종료한다. 실패는 인라인 재시도로 복구하며 추가 Zone 없이 원래 Zone에서 생성하는 기본 경로는 유지한다. 리소스·사용자·프로젝트·경로 문맥 변경 및 닫힌 폼의 이전 응답은 무시한다.

정기/즉시 스냅샷의 프라이머리 스토리지 복제 스위치, 조건부 스토리지 선택, 관련 `listStoragePools` 요청을 제거한다. 폼에 예전 값이 있더라도 생성 요청은 `useStorageReplication=false`를 명시하고 `storageids`는 보내지 않는다. 기존 추가 Zone 입력과 일정·보존 수·시간대·태그·즉시 스냅샷 이름/백업/정지 옵션을 유지한다. 백엔드 API와 별도의 스냅샷 사본 관리 UI는 변경하지 않는다.

컴포넌트 회귀는 지연된 빈 응답 뒤 실제 loading prop 갱신, 전체 페이지/제외 조건, 503/시간 초과/잘못된 응답과 재시도, 문맥 변경/닫기, 복제 옵션 미노출/미조회/미전송, 일반 일정의 조회 생략을 확인한다. 관련 정책 상세·공통 대화상자·관리 검사도 함께 실행한다.

UI만 변경하므로 Maven/전체 Cloud 빌드는 실행하지 않는다. WSL ext4에서 Node 14 production UI를 빌드하고 31 GFS2·32 RBD의 활성 webapp 정적 파일만 배포한다. WEB-INF/META-INF/config·기존 JAR·PID 및 별도 이미지를 비교하고 index를 마지막으로 갱신한다. 실제 대화상자·요청·정책/스냅샷 결과와 실패 후 재시도를 검증한 뒤 `V1490-31-`/`V1490-32-` 전용 볼륨·스냅샷·정책을 정리한다. 기존 FT 작업은 별도 작업 트리에서 보존한다.
