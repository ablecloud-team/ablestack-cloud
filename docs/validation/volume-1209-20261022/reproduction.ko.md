# #1209 재현 및 검증 절차

1. 각 환경에서 전용 접두어로 공개 21개·같은 도메인 2개의 일반 디스크 오퍼링, 다른 도메인 1개, 컴퓨트·사용자/DA·프로젝트·격리 네트워크를 준비한다. 기존 운영 오퍼링·네트워크는 수정하지 않는다.
2. User의 listDiskOfferings에서 keyword=전용-Disk-, pagesize=10, page=1/2/3을 조회한다. count=23, 페이지별 10/10/3과 연결 ID를 대조한다. 다른 도메인의 오퍼링이 제외되는지 Admin/DA/User/Project로 확인한다.
3. 수정 전 VM 생성의 데이터 디스크 선택기에서 API의 전체 후보와 달리 total=10·1페이지뿐인 증상을 확인한다. 수정 후 UI 모듈을 정적 파일만 배포하고 WEB-INF/META-INF/config/JAR/PID와 HTTP 200을 보존한다.
4. 실제 VM 생성 ROOT/DATA 선택기에서 전용 후보 검색→10개/20개 페이지→마지막 후보 선택→다른 페이지/검색/해제→원래 선택을 확인한다. 선택된 UUID·크기/IOPS/개수와 다른 선택기의 검색/페이지가 보존되는지 확인한다. 미선택은 데이터에만 표시되고 이전 객체를 비운다. KVDO 적격성 필터는 전체 후보를 대상으로 페이지 전에 적용한다.
5. 특정 listDiskOfferings 응답만 실패시킨다. 나머지 폼/세션을 유지하고 생성 차단·명시적 오류·재시도를 확인한다. 같은 범위의 완전한 후보 교체·후속 페이지 실패 시 이전 후보 보존·소유자 전환의 늦은 응답 무시는 focused 검사와 구분한다.
6. User 기본 보기에서 마지막 페이지의 disk23을 선택하고 사용자 지정 데이터 크기 1GiB·개수 1, 전용 컴퓨트·네트워크·테스트 이름으로 실제 Stopped VM 생성을 실행한다. UI POST의 datadisksdetails 디스크 ID/크기/개수를 API/DB VM·볼륨과 대조한다. 게스트 부팅/I/O 검증으로 확대하지 않는다.
7. API/DB에 생성된 VM/볼륨을 정리하고 전용 네트워크·프로젝트·계정·도메인을 제거하며 컴퓨트/디스크를 Inactive로 유지한다. 활성 잔여 0·기존 운영 inventory 동일·관리 파일/프로세스/정적 파일·HTTP/호스트 상태를 대조한다. 새 이미지가 실제 생성됐다면 Cloud 정리 후 해당 경로도 확인한다.
8. 브라우저 중단 패턴·캐시 등 임시 설정을 복원하고 로그아웃·검증 탭만 종료한다. 증거와 한계를 누적 PR에 기록한 뒤 #1209를 개별 구현 완료 기준으로 종료한다.
