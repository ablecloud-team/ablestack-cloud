# SS-13 스냅샷 상세 설계 (#1486)

기준 커밋: `5ed664e6c7e4d0cdcacc18794dddae3c405a16ff`. Epic 브랜치: `dhslove/epic-1473-storage-snapshots`.

## 배치와 의미

가상머신 상세와 같은 ResourceLayout의 7:17 카드/탭 배치를 유지한다. 공통 InfoCard의 제목, 상태, ID 복사, 소유자, 도메인, 생성일과 태그를 재사용한다. 카드의 자원 필드 간격 CSS를 공유하고 가상 용량, 세컨더리 백업 물리 크기, 원본 볼륨, 연결 VM, 사본 Zone을 배치한다. 오른쪽 상세는 기존 resource-details-list 규격으로 유형, 주기, 볼륨 유형/현재 상태, VM 상태, 복원 조건과 사본 속성을 표시한다. 중복 ID/이름/소유자/생성일은 제거한다. 기존 작업 영역과 안전 확인 대화상자를 유지하며 새 대화상자는 만들지 않는다.

가상 용량과 세컨더리 백업 물리 크기를 구분한다. 단위는 SS-12 크기 포맷을 재사용한다. 0은 0 B로, API 누락은 미확인으로 표시한다. 사본별 physicalsize가 API에 없으면 논리 가상 용량만 보여 주고 한계를 설명한다. Primary/Image는 프라이머리/세컨더리로 번역하고 저장소 ID, Zone, 상태, 가용성은 사본 계약과 일치시킨다.

## 데이터와 안전성

논리 스냅샷 1건(showunique=true, includesnapshotcontext=true), 전체 사본 페이지(showunique=false), 권한이 있는 현재 볼륨/VM, 설정이 허용하는 부모 스냅샷을 하나의 상세 읽기로 결합한다. ID, 프로젝트, 컨텍스트 버전, 사본 건수/중복, 부모의 원본 볼륨/소유 범위를 검사한다. 조회 제한 시간은 20초다.

원본 삭제/조회 권한 부족은 관련 링크만 제거하고 이유를 표시한다. 세컨더리 백업으로 새 볼륨을 만드는 기존 진입은 유지한다. 부모 링크는 조회된 동일 소유 범위의 스냅샷만 허용하고 프로젝트 query를 전달한다. 체인은 snapshot.show.chain.size 기능 설정이 true일 때만 표시한다. 체인 데이터 누락을 부모 없음이나 0으로 추정하지 않는다.

동일 대상 갱신 실패 시 이전 카드와 태그를 유지하고 오류/재시도를 제공하되 스냅샷 작업은 잠근다. 접근 거부/대상 소실은 이전 정보를 비운다. 스냅샷, 프로젝트, 사용자, 역할, API 권한, 체인 설정이 바뀌면 이전 읽기를 무효화한다. 탭 이동은 동일 대상 정체성을 바꾸지 않는다. 태그 완료/재시도/범위 보호는 SS-11의 독립 조회와 작업 잠금을 재사용한다.

## 검증 경계

각 클러스터에 독립 도메인, owner/other/domainadmin 계정, 프로젝트, 원본 삭제/연결 DATA/ROOT 포함 7개 스냅샷과 전용 VM을 준비한다. 읽기 전용 역할로 실제 API 제한도 확인한다. API와 독립 SQL, 백업 이미지 qemu-img 정보를 비교하고 UI에서 링크, 태그 job 완료, 오류/권한/늦은 응답, ID 복사, 라이트/다크 390/768/1280px를 확인한다.

실제 두 클러스터의 부모 체인이 없는 경우 이를 명시하고 긍정적인 부모 링크/체인 크기는 응답 주입으로 별도 검증한다. DB 체인을 조작하지 않는다. Zone/이벤트/코멘트 탭 표준화는 #1487, 남은 대화상자는 #1488, 전체 통합 회귀는 #1489 소유다. 전체 Cloud CI는 이번 요청에 포함되지 않는다.
