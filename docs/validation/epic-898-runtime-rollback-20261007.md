# Epic 898: 런타임 카탈로그와 복구 기반 실제 검증

13번 테스트 클러스터에서 완료한 일부 기능의 검증 기록이다. 전체 Epic 완료 기록이 아니다. SMB AD는 사용자 요청으로 보류한다.

## 배포와 발견한 문제

관리 서버 10.10.13.10의 mold, 두 호스트 10.10.13.1/.2의 mold-agent에 기존 JAR의 변경 클래스/리소스만 적용했다. 나머지 항목의 바이트 보존을 검증했다. 관리 서버 소스 eb5c27c0f3a45ba0d506a624f660b8b8dc6f0fef, 변경 243개, 백업 /root/epic898-backup-20261007-033347, JAR SHA-256 424757f959186466aa4c24b2eb128d00259366a9524c9fff9060565dcec73760. UI는 참조 조회 실패 격리와 카탈로그 화면을 포함한 838개 정적 파일을 검증했다. 카탈로그·작업 이력 마이그레이션 Complete, 관리 서버 HTTP 200, 두 호스트 Up/Enabled.

실제 기동에서 작업 DAO의 Spring 등록 누락을 발견해 이전 JAR로 복구하고 수정했다. 실제 UI 게시 검증에서 카탈로그 JSON의 DAO 255자 잘림도 발견해 카탈로그와 복구 스냅샷/결과 필드의 길이를 수정했다. 단위 테스트만으로 배포 완료를 판단하지 않았다.

## 서명 번들과 실제 UI

검증용 버전 epic898-20261007-foundation, 공개키 ID epic898-test를 사용했다. 개인키는 프로세스 메모리와 memfd에서만 사용하고 파일로 남기지 않았다. 운영용 고정 키로 취급하지 않는다. 관리 서버 loopback 전용 HTTP 서버로만 제공했다.

- Manifest SHA-256: b06d1656799571817abfe0786d46aefbdf01783834462dd806bc8c861637f62c
- 크기 57,206바이트, ABI/schema 1/1, serviceImpact NONE

전용 자원 epic898-ui-test-01에서 실제 UI 사전 점검 → 업그레이드 COMPLETE → 롤백 ROLLED_BACK → 최신 버전 재적용 COMPLETE를 수행했다.

## NFS 연결 유지

기존 SystemVM을 클라이언트로 사용해 전용 자원의 NFSv4.2 공유를 마운트했다. 기존 nfs-test 데이터 볼륨의 파일에는 쓰지 않고 검증 공유에만 테스트 파일을 생성했다.

같은 마운트의 연속 append와 기준 내용 읽기 480회가 IO_COMPLETE로 끝났다. 카운터 1~480 순서 일치, 오류 없음, 초 단위 기록의 최대 인접 간격 1초였다. 업그레이드·롤백·재적용이 이 구간에 포함됐고 완료 후 임시 마운트를 해제했다. 최종 파일 SHA-256은 b2270bd6e9d24c3ecd30a9438d3509d4c85530890f6cff6a2d54b697beb5b461이다.

기존 nfs-test도 실제 UI로 최신 런타임을 적용했다. 전후 NFS PID 1916과 2049 리스너가 유지됐으며 두 SystemVM에서 새 operation preflight가 정상 응답했다.

## 설정 실패와 복구

전용 자원의 NFS 읽기 전용 변경을 실제 UI에서 요청하고 해당 SystemVM에만 한 번의 NFS apply 실패를 주입했다. 원래 진입점은 실패 반환 전에 복원되며 미사용 시 180초 후 자동 복원하도록 제한했다.

작업 b6c67228-661f-4d4e-9a4a-bacfcf226002는 DB 변경 후 실행 적용 실패 → 이전 스냅샷 복원 → NFS 재적용 → live health 검증을 거쳐 ROLLED_BACK/100%로 끝났다. 이전 스냅샷은 4,957자, schema 1, 테이블 5개로 온전히 보존됐고 실패한 변경의 LKG는 생성되지 않았다.

기존 readOnly false와 전체 config, Ready 상태가 복원됐다. 볼륨·파일시스템 UUID와 데이터 파일 해시가 동일했다. 진입점은 다시 서명된 버전 symlink이고 스크립트 해시가 일치했다. 실제 UI에서 오류와 기존 읽기/쓰기·Ready 행을 함께 확인했다. 이 구성 복구에서는 NFS 프로세스가 재적용됐다. 런타임 코드 교체의 연속 I/O 검증과 구분한다.

## 검사 범위와 남은 작업

첫 구현 묶음 backend 57개/guest 6개, JSON 저장 수정 9개 및 26개 모듈 package, live health 강화 54개 및 package, 공통 큐 범위 2개, UI 조회 범위 기존 222개 테스트가 통과했다.

이 기록으로 전체 이슈를 종료하지 않는다. SMB/iSCSI/NVMe-oF 실제 데이터 경로, 재부팅, 대용량 준비 재개, 데이터 보존 삭제, 백업·복원/템플릿 교체, 공통 권한 정책, 오퍼링·용량·기존 볼륨 생성, 최종 UI 정리 및 각 기능의 실제 UI 검증을 이어서 수행해야 한다. 운영용 고정 서명 키가 준비됐다고 보고하지 않는다.
