# #1475 스냅샷 다운로드 설계

Epic #1473 / SS-02. 대상은 31 GFS2, 32 RBD의 KVM 세컨더리 스냅샷 다운로드다.

## 계약

원본 볼륨 형식과 백업 파일 형식은 다를 수 있다. 원본 볼륨이 삭제되어도 스냅샷의 논리 용량과 실제 백업으로 판별한다. #1474의 `SnapshotImageMetadata.inspect`를 SSVM에서 사용하며 서버 모듈이 세컨더리 모듈을 참조하는 순환 의존성은 만들지 않는다.

기존 `CreateEntityDownloadURLCommand`에 부작용 없는 `inspectOnly` 요청과 응답 메타데이터를 추가한다. 이전 SSVM이 검증 메타데이터를 반환하지 않으면 업그레이드 필요 오류로 실패한다. 관리 서버는 실제 형식을 확장자 생성에 사용하며 SSVM은 링크 생성 직전 다시 판별하여 파일명과 일치하는지 확인한다. RAW는 독립적인 스냅샷 논리 용량과 파일 길이가 일치해야 한다.

API 완료는 `DOWNLOAD_URL_CREATED`이며 파일 전송 완료를 뜻하지 않는다. 응답은 기존 `snapshot.url`과 함께 `filename`, `format`, `size`(가상 용량), `physicalsize`(전송 파일 길이)를 반환한다. URL DB 저장 실패 시 새 링크를 폐기한다. 다운로드 요청은 Snapshot 리소스별 비동기 동기화 대상을 지정한다.

## 수명주기와 실패

기존 링크는 재검증 없이 재사용하지 않는다. 재요청은 기존 링크를 폐기하고 새 주소를 생성하며, 검사 실패 시 성공 응답이나 새 export 디렉터리를 남기지 않는다. 정상 스냅샷 삭제도 먼저 링크를 폐기한다. 세컨더리의 링크·임시 파일 삭제는 검증한 경로만 다루며 원본 백업과 다른 디렉터리 내용은 보존한다.

다운로드 링크는 기존 Apache bearer URL 계약을 유지한다. API 권한과 링크 보유자의 HTTP 접근은 다르다. URL 만료 정책은 기존 관리 서버 정리 주기를 사용하며, UI에서 링크 보안과 만료·접근 실패 시 재생성 방법을 안내한다. 주기 전체 경과를 기다리는 시험과 전용 링크에 정리 명령을 실행하는 제어 시험은 결과 보고에서 구분한다.

## UI

다운로드 대화상자는 가상머신 표준 `MoldDialog` md(720px), 공통 제목·닫기·푸터·테마를 사용한다. 상세 화면에 별도 진행 패널을 추가하지 않고 기존 상단 알림과 공통 작업 상세를 사용한다. 실제 파일 검사가 끝나면 한글로 다운로드 준비 완료를 표시하고 구조화한 파일 메타데이터와 안전한 링크를 보여준다. HTML 문자열 응답은 제거한다.

기존 대상 고정·최신 상태 검사·계정/프로젝트 문맥 확인·전송 결과 불명 시 재제출 보호를 유지한다. 완료 응답의 프로토콜, 파일명, 확장자, 형식과 용량이 유효하지 않으면 완료로 확정하지 않는다. 링크와 텍스트는 Vue 바인딩으로 처리하고 새 창 링크는 `noopener noreferrer`를 사용한다.

## 검증과 배포

새 전용 fixture만 사용한다. QCOW2/RAW × GFS2/RBD에서 API 완료, DB 논리 용량·URL, 실제 HTTP 200/206 파일, qemu-img 형식·가상 용량, 원본/다운로드 SHA256, 앞·뒤 데이터 패턴을 대조한다. 누락·손상·읽기 거부와 링크 재생성·폐기를 검증한다. RAW fixture는 전용 백업의 변환본이며 제품이 RAW 백업을 기본 생성한다고 표현하지 않는다.

변경 Maven 모듈만 WSL ext4에서 빌드한다. 32 SSVM의 기존 Diplo 라이브러리는 유지하고 다운로드 메서드만 ASM으로 반영하여 다른 메서드와 기존 스냅샷 기능을 보존한다. UI는 정적 파일만 배포하고 WEB-INF/META-INF·설정·JAR을 보존한다. 전체 Cloud 빌드·GitHub Actions·qemu 패키지 빌드는 이 작업에 포함하지 않는다.
