# #1484 공통 InfoCard 태그 비동기 작업 설계

부모 Epic #1473, 구현 브랜치 `dhslove/epic-1473-storage-snapshots`. 기준 커밋 `6290859f3a5253ca46a0d8e0064f8b87d281beba`.

## 문제와 변경

기존 InfoCard는 createTags/deleteTags 접수 응답의 finally에서 listTags를 호출했다. 비동기 job의 완료를 기다리지 않아 최종 값이 누락되고, 중복 생성의 실제 job 실패도 화면에 표시되지 않았다. 삭제 태그의 기본 close 동작은 완료 전에 표시를 지웠다.

기존 태그 영역을 공통 ResourceTags로 분리한다. Snapshot과 UserVm을 포함한 기존 InfoCard 태그 대상이 이 컴포넌트를 사용한다. 가상머신 상세 화면의 카드·작업 도구 모음·탭 구조와 기존 소유권 판정은 유지한다. 새로운 대화상자는 만들지 않는다. 태그 상태·오류·재시도는 태그 영역에만 표시하며 전체 상세 화면에 작업 패널을 추가하지 않는다.

## 제출·추적 계약

1. 대상 UUID/유형, 실제 프로젝트 소유자, 태그 key/value를 복사해 고정한다.
2. 제출 전에 같은 대상의 전체 태그를 새로 읽는다. 조회·범위·권한 확인이 실패하면 POST를 보내지 않는다.
3. POST 접수는 완료가 아니다. 기존 createJobTracker로 같은 job ID를 조회한다.
4. jobstatus=1이면 태그를 재조회한다. 삭제 close의 기본 동작을 막아 완료 및 재조회 전까지 태그를 유지한다.
5. jobstatus=2 또는 명확한 API 거부는 실패 사유와 명시적 동일 작업 재시도를 제공한다. 같은 실패를 확인/Enter로 자동 반복하지 않는다. 재시도도 최신 태그를 읽고 새 job을 한 번만 제출한다.
6. job 조회 장애는 1.5초 간격과 최대 2회 재시도를 사용한다. 전체 추적은 120초로 제한한다. 결과 미확인 상태에서는 추가 변경을 잠그고 기존 job의 상태 재확인을 제공한다. 조회 재시도는 POST를 보내지 않는다.

상태는 idle → preparing → submitting → pending/retrying → succeeded/failed/unknown이다. pending/retrying/unknown에는 중복 변경을 허용하지 않는다. 성공 후 listTags 실패는 job 성공과 별개로 표시하고 조회 전용 새로고침을 제공한다. 일반 같은 범위 조회 장애는 기존 태그를 유지하지만 401/403/권한 거부에서는 기존 태그를 숨긴다.

## 범위·보존

서버·사용자·계정·도메인·역할 유형·로그인 세션을 보안 식별자로 사용한다. 선택 프로젝트/전체 프로젝트, 대상 UUID/유형/소유자를 추가해 작업 문맥을 분리한다. sessionStorage 키에는 식별자/문맥의 MD5를 사용하고 영수증 값에 토큰을 기록하지 않는다. 이는 키 구분이며 암호화 수단이 아니다.

화면·계정·프로젝트·API 사용 권한이 바뀌면 표시/읽기 구독을 해제하고 이전 태그와 상태를 숨긴다. 늦은 읽기 결과와 이전 추적 결과는 무시한다. 늦게 도착한 POST 영수증은 원래 대상에만 보존하고 원래 화면에 복귀했을 때 같은 job을 조회한다. 여러 화면 구독 중 하나가 사라져도 다른 활성 구독의 추적은 중단하지 않는다. 새 로그인 식별자로 전환하면 이전 태그 영수증을 폐기한다.

태그 목록은 100개씩 전체 페이지를 읽고 건수/중복/대상 일치를 검사한다. 실제 소유 프로젝트 ID를 명시하고 기본 보기에서는 ignoreproject를 사용해 요청 인터셉터의 projectid=-1 자동 주입을 막는다. 권한 자체는 서버 API가 최종 판정하며 확대하지 않는다.

## 미확인 접수 제한

POST 타임아웃·503·응답 손실로 job ID를 받지 못한 경우 Cloud 태그 API에는 요청 중복 방지 키나 원래 작업을 식별하는 조회 계약이 없다. 태그 값의 존재만으로 해당 요청의 완료를 추정하지 않는다. 같은 세션의 해당 문맥은 새로고침 후에도 잠기며 조회만 허용한다. 운영자가 실제 API/job/DB 결과를 확인한 뒤 새 로그인 세션에서 작업을 이어갈 수 있다. 자동 재제출이나 UI 잠금 해제로 중복 작업을 유발하지 않는다.

## UI 기준

태그 입력은 상세 카드 폭에 맞게 key/value를 각각 한 줄로 표시하고 확인·취소를 오른쪽에 둔다. 태그와 긴 오류/작업 ID는 줄바꿈한다. 삭제 아이콘은 테마 글자색을 상속하고 검정색을 고정하지 않는다. 새로 만들거나 변경하는 대화상자는 계속 가상머신 표준을 적용하며, 나머지 목록/상세/탭/대화상자 정리는 #1485–#1488 범위다.

## 검증 경계

실제 API의 중복 생성 job 실패와 소유권 거부를 검증한다. HTTP 503/403 및 응답 지연은 실제 UI 요청에 일시적으로 주입해 통신 장애 처리를 검사하고 정상 서버 처리와 구분해 기록한다. 31 GFS2/32 RBD의 전용 개인·타 계정·프로젝트 스냅샷 및 관리자 Stopped VM을 사용한다. API 응답, job, 독립 SQL과 실제 화면을 대조하고 정상 API로 전용 자원을 정리한다. 전체 Cloud 빌드/Actions는 실행하지 않는다.
