# #1513 브라우저 최종 저장 추가 검증 - 미완료

2026-10-29 KST · Epic #1510 · Draft PR #1514

사용자는 `.tmp`에서 정상 파일명으로 전환되고 저장 완료되는 단계까지 추가 검증을 요청했다. **이 단계는 아직 확인하지 못했다.** 앞선 전체 본문·길이·QCOW2·SHA256 일치는 정상 파일명 전환의 증거로 대체하지 않는다.

## 이번 실행

- 기존 Chrome Downloads의 `.tmp` 파일 5개는 남아 있다. 수동으로 이름을 바꾸거나 파일을 복사해 브라우저 완료로 처리하지 않았다.
- 22에 별도의 1GiB explicit off/raw DATA `qa1513-22-save-off-raw-data`를 생성하고 두 위치에 구분 패턴을 기록했다. 이 전용 볼륨의 UI 추출이 성공해 링크가 생성되는 데까지 확인했다.
- 사용자가 새 Chrome Mold 탭을 전면 활성화했다고 알려 준 뒤 Windows 저장 UI 조회를 시도했다. 컴퓨터 조작 도구는 Chrome의 현재 URL을 충분히 확신해 판별할 수 없다며 이번 턴의 컴퓨터 조작을 강제 종료했다.
- 이후 브라우저 조작을 재시도하거나 다른 UI 자동화 경로로 우회하지 않았다. 실제 다운로드 클릭·정상 파일명 전환·완료 표시 확인은 미수행이다. 현재 증거로 제품 오류를 단정하거나 임의 수정·배포하지 않았다.

## 자원과 보호 대상

브라우저 조작 종료 뒤 정상 API로 새 시험 볼륨과 디스크 오퍼링을 정리했다. 해당 Primary 이미지·Secondary 파일·Image 참조·SSVM symlink가 남지 않으며 링크는 HTTP 404다. 오퍼링의 비활성 이력은 보존한다. 기존 `.tmp` 파일은 진단 근거로 보존했다.

22 `rocky98-perftest`에 전원·디스크·QGA·마이그레이션 요청을 보내지 않았다. 최종 QEMU PID `219715`, 시작 tick `191152358`은 실행 전과 같다.

## 추적 상태

#1513은 정상 파일명·저장 완료 추가 기준이 남아 있으므로 다시 OPEN으로 추적한다. Epic PR의 CL-08은 구현/17개 조합 및 오류 복구 검증 완료와 브라우저 최종 저장 미검증을 구분한다. 제품 코드나 배포를 변경하지 않았고 빌드를 실행하지 않았다.
