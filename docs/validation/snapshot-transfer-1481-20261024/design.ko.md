# #1481 스냅샷 보관·복사 설계

## 범위와 기존 계약

Epic #1473의 #1477 보관·강제 정리, #1479 작업 대상 고정·비동기 보호, #1480 사본 계약을 사용한다. 일반 KVM/NFS Secondary 복사를 개선한다. StorPool 전용 복제 스위치와 Primary 풀 선택은 역할·스토리지·capability와 관계없이 UI에 제공하지 않는다. 공급자 전용 API 인자는 기존 경로를 유지한다.

## 읽기 전용 대상 조회

새 API `listSnapshotCopyTargets(id, sourcezoneid)`는 스냅샷 ACL을 확인한 후 원본 적격성, 원본 Zone, 가용 대상, 제외 사유와 `scopehash`를 반환한다. 실제 응답은 `listsnapshotcopytargetsresponse.snapshotcopytargets`다.

원본은 BackedUp KVM 스냅샷의 Ready NFS Secondary 사본이어야 한다. 강제 정리 잔여, 마운트 등록 미완료, 세컨더리 에이전트 연결 불가를 구분한다. 대상은 조회 권한이 있는 다른 Zone으로 제한한다. 비활성·Edge·Secondary 미구성·읽기 전용·용량 부족·마운트 미완료·에이전트 연결 불가·진행 중인 복사·불안정하거나 모호한 참조를 제외한다.

기존 Ready 사본은 완료 대상으로 표시하고 UI 재선택을 막는다. 실패 참조의 재시도는 원래 저장소에 고정한다. 스냅샷 체인의 기존 대상 저장소와 충돌하는 선택은 거부한다. 저장소 식별자·이름은 Root 관리자에게만 반환하며 다른 계정의 스냅샷은 대상 조회 전에 접근을 거부한다.

해시는 스냅샷 참조·사용자·원본 Zone/저장소·대상 Zone 상태·저장소 URL/마운트·가용성을 포함한다. 실물 손실은 사전 DB 조회만으로 단정하지 않고 실행 시 별도 검증한다.

## 실행과 완료 판정

일반 복사는 삭제·보관과 같은 스냅샷 잠금을 사용한다. 선택한 모든 대상을 첫 전송 전에 재검증하고, 선택한 저장소를 실제 체인 복사에 전달한다. 대상별 실행 직전에도 변경 여부를 확인한다.

HTTP 전송과 이미지 검증이 모두 성공한 뒤에만 완료 Zone, 사용량과 SNAPSHOT.COPY 이벤트를 기록한다. 검증한 가상 용량과 물리 용량을 사본 참조에 저장한다. Secondary 사용량과 이벤트의 size는 Cloud 재계산과 같은 물리 바이트 기준이고, virtual_size는 스냅샷 가상 용량이다. 같은 Zone 사본의 재확인은 추가 사용량·이벤트를 만들지 않는다.

검증 실패 사본은 실패 상태와 안내를 남겨 재시도할 수 있게 한다. 일부 대상 실패는 전체 비동기 작업 실패로 반환하며 완료·실패 Zone을 구분한다. 완료 사본은 보존한다. 기존 사본을 API로 다시 요청하면 실물을 재확인한다.

## UI와 대화상자 표준

보관 작업은 스냅샷 상세 작업 메뉴에서 공통 StorageSnapshotActionDialog로 진입한다. 기존 사본 확인, 기존 Secondary 재사용, 백업 후 Primary 정리, 정리 재시도의 영향을 진단 결과에 맞춰 안내하고 확인 체크박스를 요구한다.

복사는 Zone별 작업에서 SnapshotCopyDialog로 진입한다. 원본 Zone과 Secondary를 고정하고 다른 Zone의 Secondary 대상만 선택한다. 실제 빈 대상, 조회 실패, 권한 거부, 미지원 사유, 비동기 실패를 구분한다. 조회 실패는 기존 검토 정보를 보존하되 제출을 막고, 권한 거부는 이전 대상과 선택을 제거한다.

두 대화상자는 가상머신의 공통 MoldDialog md, 공통 본문 여백·스크롤·하단 취소/실행 버튼 구조와 테마 변수를 사용한다. 상세 페이지의 중복 정보 표는 추가하지 않는다. 진행·완료·실패는 기존 알림과 공통 작업 상세에서 확인한다.

제출 직전 최신 상태와 해시를 확인하며, 화면·프로젝트·역할·로그인 범위 변경과 늦은 응답을 차단한다. 기존 작업 lease, customjobid, 응답 유실·중복 제출 보호를 유지한다.

## 실제 검증 구성

31(GFS2), 32(RBD)에 새 전용 볼륨·스냅샷과 Zone/Secondary 저장소를 구성한다. 대상은 같은 SSVM 안의 별도 AgentShell 프로세스와 서로 다른 실제 NFS 경로다. 각 프로세스는 별도 설정·로그·인증서 사본을 사용하고 TLS 검증을 유지한다. 기존 SSVM, 호스트, 볼륨과 설정을 재배치하지 않는다.

시험용 NFS 마운트는 nosharecache로 분리한다. 실물 검증 경로를 새 image_store의 parent에 사실대로 등록한다. 스냅샷 사본 참조·복사 결과·성공 이벤트를 수동 생성하지 않는다. 데이터는 제품의 HTTP 다운로드/복사 명령으로 전송한다.

대상 B의 전용 마운트만 읽기 전용으로 만들어 A 성공/B 실패를 확인한 후 복구·재시도한다. API/UI 요청, 작업 완료 상태, 사본·Zone·사용량·이벤트 DB, 이미지 형식/가상 용량/데이터 패턴/SHA-256을 대조한다. 전체 SSVM 신규 VM 프로비저닝과 별도 물리 NAS 사이의 전송 성능 검증은 이 fixture의 범위 밖이다.
