# 볼륨 대화상자 정렬과 정기스냅샷 상세 탭

대상: Epic #1422 / Draft PR #1435, #1433 완료 후 사용자 요청 보완.

## 문제와 변경

- 공통 대화상자는 960px이지만 마이그레이션·오퍼링 변경의 폼은 500px, 정기스냅샷은 800px 제한이 남아 있었다. 내부 폼을 본문 너비에 맞추고 좁은 화면에서는 부모 안에서 줄어들도록 한다.
- 정기스냅샷 등록 대화상자 안에 등록 폼과 정책 목록이 함께 있어 현재 볼륨의 정책을 확인하려면 작업을 열어야 했다. 볼륨 상세의 스냅샷 탭 다음에 `정기스냅샷` 탭을 추가하고 조회·삭제를 이동한다.
- 대화상자는 대상 볼륨과 등록 필드만 표시한다. 기존 정책 조회는 등록된 주기를 비활성화하기 위해 내부적으로 유지한다. 조회 실패 시 등록을 막되 취소·닫기는 가능하게 한다.
- 새 탭은 주기, 실행 시각·요일·일자, 시간대, 유지 수, 존, 스토리지, 태그를 표시한다. API 권한에 따라 탭·삭제·관련 자원 링크를 제공한다.
- 갱신 실패 시 기존 행과 세션을 보존하고 재시도한다. 인증 실패, 볼륨·사용자·프로젝트 변경 때 이전 데이터와 늦게 도착한 응답이 섞이지 않도록 한다.
- 정책 생성·삭제는 중복 제출과 컨텍스트 변경을 방어한다. 마이그레이션의 공통 대화상자 busy 상태도 실제 제출 상태에 연결한다.
- 실제 UI에서 부모 상세의 백그라운드 갱신은 loading을 바꾸지 않고, 응답 내용이 같으면 볼륨 객체도 교체하지 않는다는 점을 확인했다. ResourceView가 제공하는 resourceReadPending 완료 상태를 관찰해 활성 정책 탭을 다시 조회한다. 같은 객체가 유지되는 조건을 회귀 테스트로 검증한다.
- 정기스냅샷 폼의 작은 화면 열 너비를 24로 명시한다. 화면이 좁을 때 시간·요일·유지·시간대 필드가 내용 크기로 축소되지 않고 한 줄씩 표시된다. 월간 일자는 `매월 28일` 형태로 번역한다.

## 검증 범위

변경 UI의 린트, 관련 Jest 회귀, 최적화 운영 UI 빌드, 31 GFS2·32 RBD의 실제 브라우저·API·DB 검증을 수행한다. 배포 전에 만든 월간 정책을 유지한 채 일간 정책을 UI에서 생성·삭제하고 정책 없는 다른 볼륨과 구분한다. 각 대화상자의 폼 너비, 고정 푸터, 좁은 화면과 테마를 확인한다.

정적 UI만 배포하며 관리 JAR, PID, WEB-INF, META-INF, config.json 및 기존 추가 파일을 보존한다. 전체 Cloud 빌드와 엔진 변경은 범위에 포함되지 않는다. 통합 회귀·Epic 종료는 기존 #1434에서 진행한다.
