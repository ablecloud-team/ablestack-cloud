# 스냅샷 볼륨 생성·복원 대화상자 설계

## 적용 범위

Epic `dhslove/epic-1473-storage-snapshots`에서 사용자가 승인한 목업을 두 대화상자에 적용한다. 상세 화면의 좌측 정보 카드·탭 배치와 기존 알림/작업 상세는 유지한다. 전체 대화상자 표준화 #1488 중 볼륨 생성과 원본 볼륨 되돌리기 범위다.

## 공통 화면 계약

공통 `MoldDialog`의 md(720px) 크기, 고정 헤더·푸터, 화면보다 작은 최대 폭, 본문 스크롤을 사용한다. 헤더 16×24px, 데스크톱 본문 24×28px·푸터 16×28px, 모바일 본문·푸터 16px를 적용한다. 폼 항목 사이 24px, 레이블과 입력 사이 8px로 확보한다. 이는 간격을 일괄 축소하는 변경이 아니라 폼 구조와 줄바꿈을 바로잡아 겹침을 제거하는 변경이다.

가상머신의 공통 MoldDialog와 헤더/정보 카드/탭 컴포넌트는 수정하지 않는다. 기존 VM의 소형 520px 연결 대화상자를 그대로 복제하는 것이 아니라 승인 목업의 공통 md 프리셋을 사용한다. 대상 화면에서 공통 헤더·푸터·키보드·포커스 방식을 재사용한다.

## 볼륨 생성

- 상세에 이미 있는 이름/UUID/상태/원본/소유자/Zone 요약 표와 중복 갱신 버튼을 제거한다. 입력은 이름 → Zone → 소유자 → VM 연결 순서로 배치한다.
- 관리자 소유자 선택은 폼 안에 div로 삽입해 중첩 form을 제거한다. 소유자 유형은 한 줄, 도메인/계정은 데스크톱 두 열·모바일 한 열이다. 다른 호출자는 기존 독립 form과 자동 초점을 유지한다.
- VM 연결 스위치와 레이블을 한 줄에 두고, 선택 시 VM·장치 번호를 표시한다. 불필요한 영문 deviceID 설명은 제거하고 기존 장치 번호 도움말/검증은 유지한다.
- 푸터는 취소/생성, 제출 중 로딩 및 닫기·취소·중복 제출 차단을 유지한다. 이름과 선택 문구를 한글로 표시한다.
- 원본 소실은 실제 복구에 필요한 안내만 표시한다. 조회 오류는 입력을 보존하고 인라인 재시도를 제공한다. 기존 작업이 미종결이면 상단 알림의 작업 상세로 안내하고 재제출을 계속 차단한다.

## 스냅샷 복원

복원 영향 경고에 원본 볼륨과 선택 스냅샷 이름을 문장으로 표현한다. 불필요한 메타데이터 표는 없앤다. 경고 → 영향 확인 체크박스 → 취소/복원 버튼을 배치하며, 긴 이름을 줄바꿈한다. 복원 버튼은 위험 작업 표시를 유지한다.

원본 VM의 상태가 바뀌거나 조회에 실패하면 제출 전에 차단하고 확인 체크를 초기화한다. 재시도는 현재 상태만 조회한다. 처리 중 빈 컨테이너 위 스피너가 잘리던 현상은 정상 문맥의 빈 안전 요약을 렌더하지 않도록 수정한다. 버튼의 처리 표시와 잠금은 유지한다.

## 안전성과 테마

대상 UUID/작업 종류·제목을 열 때 고정한다. 제출 직전 원본·VM·권한·소유자·프로젝트·Zone과 fingerprint를 기존 SS-06 검증기로 확인한다. 별도 업무 가용성 규칙을 추가하지 않는다. 기존 registry의 동일 pending 판정을 화면 안내와 제출 잠금에 공유한다. customjobid·알림·F5 복원·기존 결과 조회 경로는 유지한다.

명시적인 기존 테마 토큰을 레이블, 입력값, placeholder, 선택값, 체크박스, 오류·도움말, 숫자 입력, 비활성 버튼에 적용한다. 범위는 두 스냅샷 대화상자에 한정한다. 일반 VM 대화상자의 기존 색상까지 바꾸지 않는다.

## 검증

31 GFS2·32 RBD에서 각 대화상자의 라이트/다크, 320/390/768/1280px를 측정한다. 레이블·입력·소유자·긴 이름·조건부 VM 선택/장치 번호·오류/처리 중 상태의 겹침, 가로 넘침, 실제 글자 색/대비를 확인한다. Escape와 버튼/키보드 초점 복귀를 확인한다. 고정 푸터로 이동한 제출 버튼에서 Ctrl+Enter의 keyup을 이어 받아 폼의 기존 키보드 제출을 유지한다.

전용 fixture로 정상 생성/연결, 원본 없는 스냅샷 생성, 복원 데이터 0xa5→0x5a, VM 상태 변동 차단, 조회 오류/재시도, 응답 유실·연속 클릭·F5 잠금·동일 UUID 결과 조회를 검증한다. API/DB와 GFS2/RBD 실물 데이터를 대조한 뒤 전용 자원만 정리한다. 전체 Cloud 빌드/Actions·qemu 빌드는 포함하지 않는다.
