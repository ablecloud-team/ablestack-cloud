# #1485 스냅샷 목록 표준화 설계

기준 Epic 브랜치 `dhslove/epic-1473-storage-snapshots`, 시작 HEAD `c7fc749f8e7d4cd4cfbaedc534b3380b15b1d9ab`.

## 구성과 범위

31·32의 실제 `/vm` 목록을 기준으로 기존 AutogenView, ListView, ActionButton, SearchView, ResourceContextMenu, Pagination을 재사용한다. 공통 ListView를 복제하지 않으며 `/vmsnapshot`·VM 및 다른 자원의 기존 행동을 유지한다. 이 변경은 `/snapshot` 목록에만 새 배치를 적용한다. 상세·탭·나머지 대화상자 정리는 #1486–#1488 범위다.

작업은 텍스트가 있는 스냅샷 생성 및 선택 시 삭제, 보조 복구 아이콘/프로젝트 범위, 작업 영역 마지막 업데이트 순서로 둔다. 검색은 오른쪽에 배치하고 좁은 화면에서는 다음 줄에 전체 폭으로 배치한다. 제목/도움말은 별도 공통 breadcrumb를 사용한다. VM 공통 표의 middle 밀도·선택·열 선택·페이지 구성과 행/선택 문맥 메뉴를 사용한다. 긴 표는 내부에서 가로 스크롤하여 한글 열 제목이 세로로 잘게 나뉘지 않게 한다.

## 생성 진입

주 생성 버튼은 기존 볼륨 목록으로 이동한다. 현재 프로젝트·Zone·소유 범위만 전달하며 스냅샷 이름/태그/주기는 볼륨 검색 조건으로 오인 전달하지 않는다. 사용자가 원본 볼륨을 선택하고 기존 작업 > 스냅샷 생성 경로에서 생성한다. 볼륨이 없다면 기존 볼륨 생성 기능을 사용할 수 있다. 이 버튼 자체는 생성 API를 제출하지 않는다. 새로운 대화상자를 만들지 않으며 기존 VM 표준 MoldDialog의 안전 검증/작업 흐름을 재사용한다. StorPool 전용 옵션을 노출하지 않는다.

## 표시 계약

물리 크기와 논리(가상) 크기를 별도 열로 표시한다. B/KiB/MiB/GiB/TiB/PiB 동적 단위를 사용하고 0은 `0 B`, 누락·유효하지 않은 값은 `미확인`으로 표시한다. MANUAL/HOURLY/DAILY/WEEKLY/MONTHLY/INTERNAL은 수동/매시간/매일/매주/매월/내부로 번역한다.

사본 조회는 per-copy 값을 사용한다. 현재 API의 copy에는 논리 크기가 있으나 물리 크기는 생략되며, top-level physicalsize의 기본 0은 해당 사본의 측정값이 아니다. 이 경우 물리 크기는 미확인으로 표시한다. DB에 물리 크기가 존재한다는 이유만으로 UI가 API에 없는 값을 추정하지 않는다.

이전 기본 열 선택을 보존한 사용자는 최초 1회 가상 크기 열을 추가한다. 그 외 사용자 지정 열은 유지한다. SNAPSHOT_LIST_COLUMNS_V1:<userId>에 논리/사본 모드의 명시적 열 선택을 각각 저장한다. 공통 열 캐시가 달라져도 전용 선택을 우선 복원하며 명시적 메뉴 조작일 때만 갱신해 초기 스키마 적용이 숨김 설정을 덮어쓰지 않게 한다. 사본 모드의 필수 사본/스토리지 열과 선택/변경 금지는 유지한다.

## 조회·선택·안전

#1482·#1483의 서버 정렬/동률 ID 보조키, 검색·URL·소유 범위·페이지 크기 계약을 그대로 사용한다. 허용되지 않은 정렬을 UI에서 새로 제공하지 않는다. 조회는 20초 제한의 preserveOnFailure GET을 사용한다. 응답 항목/건수/페이지 길이/중복 식별자를 확인하고 JSON 속성 순서에 의존하지 않고 실제 count를 사용한다.

같은 범위 갱신은 기존 행·건수·선택과 마지막 성공 정보를 보존한다. 진행/실패 중에는 체크박스와 행/다중 변경을 차단하고 오류 사유·재시도를 표시한다. 실패를 0건 성공으로 바꾸지 않는다. 401/403/431/432/531은 행·선택을 지운다. 검색/페이지/프로젝트/계정/로그인/역할이 바뀌면 이전 결과를 지우고 늦은 응답을 무시한다. 정상 재조회 후에만 변경을 허용한다.

행은 키보드로 포커스할 수 있고 Shift+F10/ContextMenu로 기존 문맥 메뉴를 연다. Escape로 닫으면 기존 공통 메뉴가 행으로 포커스를 복원한다. VM과 같은 선택 묶음 동작을 유지한다. 단일 문맥 대상은 복사해 고정하며 실제 스냅샷 작업은 기존 #1479의 대상 고정·최신 상태/권한 재검증과 job 중복 제출 방지를 계속 사용한다.

## 검증

새 전용 계정 2개·프로젝트 1개·볼륨 3개와 스냅샷 26개(실제 H/D/W/M 포함)를 클러스터별로 만든다. 기본 20개 및 10/50개 페이지, 정렬·검색·주기·사본·소유 범위를 API/독립 DB로 대조한다. 실제 목록·다중 삭제/생성 진입, 같은 범위/권한/늦은 응답 오류 및 재시도, 열 선택, 라이트/다크 390·768·1280px과 키보드 포커스를 배포 UI에서 검증한다. 주입한 통신/누락 값은 실제 서버 실패나 DB 측정값과 구분한다.

UI 정적 파일만 안전하게 배포하고 WEB-INF/META-INF/config/관리 JAR 및 대용량 이미지를 보존한다. 전체 Cloud 빌드·Maven·Actions dispatch는 실행하지 않는다. 시험 자원은 정상 API로 정리하고 API/DB/스토리지 잔여와 기존 자원/FT 작업 트리 보존을 확인한다. #1489는 남은 UI 정리 후 최종 수행한다.
