CNI 구성 도움말

English

파일 가져오기와 전송 내용

등록 화면에서 UTF-8 텍스트 파일 또는 명시적인 Base64 파일을 선택합니다. 파일 미리보기는 실제 등록할 원문과 Base64를 표시합니다. ‘본문에 적용’ 전에는 기존 입력을 바꾸지 않습니다. 취소하거나 잘못된 파일을 선택해도 기존 입력은 유지됩니다.

텍스트 파일의 한글·UTF-8 BOM·CRLF/LF·마지막 개행은 바이트 그대로 보존합니다. 적용된 본문은 정확한 바이트 보존을 위해 Base64와 ‘Base64 인코드’ 선택으로 입력됩니다. Base64처럼 보이는 텍스트도 ‘텍스트 파일’로 가져오면 일반 텍스트입니다. Base64 파일은 UTF-8/ASCII 텍스트여야 하며 탭·공백·CR·LF는 정규화됩니다. Base64 파일 앞의 BOM은 Base64 문자가 아니므로 거부합니다. UTF-16이나 잘못된 UTF-8을 임의로 변환하지 않습니다.

크기 제한은 서버가 제공하는 정규화된 Base64 길이를 기준으로 합니다. 파일 읽기와 등록에서 같은 검증을 적용합니다. 빈 본문·공백만 있는 본문·초과 크기는 등록할 수 없습니다. ZIP/원격 URL 가져오기와 스크립트 실행은 제공하지 않습니다.

최소 형식 예시

기본 cloud-config:

#cloud-config
write_files: []
runcmd: []

지원되는 Jinja cloud-config 헤더:

## template: jinja
#cloud-config
write_files: []
runcmd: []

위 예시는 형식을 설명하며 네트워크 플러그인을 설치하지 않습니다. 실제 CNI 설치 설정은 Kubernetes 버전·노드 이미지·네트워크에 맞게 준비해야 합니다. 단독 Kubernetes 매니페스트 YAML을 올린다고 자동으로 적용되지 않습니다. 기존 shell 등 다른 cloud-init 형식의 적용은 해당 게스트와 제공자 경로의 지원에 따릅니다. 이 화면은 내용을 저장하며 실행 성공을 확인하지 않습니다.

변수 선언과 적용 범위

‘CNI 구성 매개변수’에 이름을 각각 직접 추가하고 Enter로 확정합니다. 예: POD_CIDR. 이름은 영문자/밑줄로 시작하며 이후 영문자·숫자·밑줄·점·하이픈을 사용할 수 있습니다. 중복 이름과 시스템 예약 메타데이터 이름은 거부됩니다. 파일 가져오기는 변수를 자동 추출하거나 값을 치환하지 않습니다.

Kubernetes 생성 마법사에서 같은 소유 범위의 CNI를 선택하고 선언한 변수의 값을 입력합니다. 일반 본문의 선언된 단순 {{ NAME }}은 서버가 값을 그대로 치환합니다. 반복·인접 토큰을 지원하며 값을 다시 템플릿으로 해석하지 않습니다. 앞에 역슬래시가 있는 \{{ NAME }}은 역슬래시를 제거한 리터럴입니다. 선언하지 않은 토큰은 원문을 유지하고 미해결로 표시합니다. 선언 변수의 값 누락이나 여분 값은 생성 전에 거부하며 빈 문자열은 명시적인 값입니다. YAML/셸 문맥에 맞는 이스케이프는 구성 작성자가 준비해야 합니다. Jinja 헤더의 {{ ds.meta_data.NAME }} 등 일반 표현식은 게스트 메타데이터 경로에서 처리되며 서버 미리보기는 실행하지 않고 원문을 보존합니다. 자동 변수 AS_NUMBER는 직접 값을 입력하지 않습니다. 해당 서버의 특수 치환 표기는 정확히 {{ AS_NUMBER }}입니다. 등록의 ‘변수 추출’에서 후보를 확인·선택하고 Kubernetes 생성의 ‘치환 미리보기’에서 서버 전송 본문과 누락·여분·미해결 값을 확인합니다. 아직 할당되지 않은 AS 번호는 자동값 대기로 남습니다.

CNI는 VM 일반 사용자 데이터 라이브러리와 다른 유형입니다. 계정·도메인·프로젝트 권한을 따르고, 이미 사용하는 Kubernetes가 있으면 삭제할 수 없습니다. 새 구성 등록으로 실행 중인 클러스터가 자동 변경되지는 않습니다.
